# Runbook: DynamoDB Data Table

## Overview
DynamoDB is a fully managed NoSQL database service used to store and retrieve data for the API. It provides high scalability and low-latency performance.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM permissions to access DynamoDB tables (read/write)
- Knowledge of the table's primary key and data structure

## Architecture
A DynamoDB table is configured with `PAY_PER_REQUEST` billing mode for flexible scaling. It is encrypted using a customer-managed KMS key (`aws_kms_key.dynamodb`) for enhanced security. Point-in-time recovery is enabled.

## Operations

### Scaling
DynamoDB with `PAY_PER_REQUEST` billing mode scales automatically based on traffic. Manual scaling is not required.

To adjust provisioned throughput (if a different billing mode were used):
1. Navigate to the DynamoDB console.
2. Select the 'DynamoDB Data Table'.
3. Go to the 'Capacity' tab and adjust 'Read capacity units' and 'Write capacity units'.

### Monitoring
Key CloudWatch metrics for DynamoDB:
- `SuccessfulRequestLatency` (Average latency for successful read/write operations)
- `ReadThrottleEvents` / `WriteThrottleEvents` (Number of requests throttled)
- `ReturnedItemCount` (Number of items returned by read requests)
- `ConsumedReadCapacityUnits` / `ConsumedWriteCapacityUnits` (Capacity consumed)

Recommended alarm thresholds:
- `SuccessfulRequestLatency` > 500ms for 5 minutes
- `ReadThrottleEvents` > 0 for 5 minutes
- `WriteThrottleEvents` > 0 for 5 minutes

### Backup & Recovery
Point-in-time recovery (PITR) is enabled for the DynamoDB table, allowing restoration to any second within the last 35 days. 

**Restore Procedure**: 
1. Navigate to the DynamoDB console.
2. Select the 'DynamoDB Data Table'.
3. Go to the 'Backups' tab.
4. Choose 'Restore to point in time'.
5. Specify the restore time and a new table name.
6. Initiate the restore process.

### Common Issues
### High Read/Write Latency
**Diagnosis**: Check `SuccessfulRequestLatency` metric in CloudWatch. If latency is high, investigate `ConsumedReadCapacityUnits` or `ConsumedWriteCapacityUnits` against provisioned capacity (if not on-demand) or general system load.
**Resolution**: For on-demand, ensure no sudden spikes in traffic overwhelm the table. For provisioned capacity, increase read/write units. Optimize queries and data access patterns.

## Rollback Procedure
1. Revert the IaC changes related to the DynamoDB table definition.
2. Apply the reverted IaC (e.g., `terraform apply`).
3. If data loss occurred and PITR is enabled, restore the table from a backup to a specific point in time, potentially requiring data reconciliation.
