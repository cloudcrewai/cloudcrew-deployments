# Runbook: DynamoDB Data Table

## Overview
The DynamoDB Data Table is a fully managed NoSQL database used to store and retrieve application data. It is designed for high scalability and performance, supporting various data structures.

## Prerequisites
- AWS CLI configured with appropriate permissions.
- IAM permissions to access DynamoDB tables (read, write, update, delete).
- Knowledge of the table's partition key and sort key (if applicable).

## Architecture
A DynamoDB table configured with `PAY_PER_REQUEST` billing mode and Point-in-Time Recovery enabled. It is encrypted using a Customer Managed Key (CMK) managed by KMS.

## Operations

### Scaling
1. DynamoDB `PAY_PER_REQUEST` scales automatically based on traffic.
2. To adjust provisioned throughput (if `PROVISIONED` mode was used): Navigate to the DynamoDB console, select the table, and modify 'Read capacity units' and 'Write capacity units'.
3. For auto-scaling with provisioned capacity: Configure Application Auto Scaling policies to adjust RCU/WCU based on utilization.

### Monitoring
Key CloudWatch metrics: 
- `SuccessfulRequestLatency` (average latency)
- `ReadCapacityUnits` / `ConsumedReadCapacityUnits` (read throughput)
- `WriteCapacityUnits` / `ConsumedWriteCapacityUnits` (write throughput)
- `ThrottledRequests` (requests rejected due to exceeding capacity). 
Recommended alarm thresholds: `ThrottledRequests` > 0 in 5 minutes, `SuccessfulRequestLatency` > 100ms P90 for 5 minutes.

### Backup & Recovery
Point-in-Time Recovery (PITR) is enabled, allowing restoration to any second within the preceding 35 days. 
**Restore Procedure**: 
1. Navigate to the DynamoDB console.
2. Select the table.
3. Choose 'Restore to point in time'.
4. Specify the desired timestamp.
5. Provide a new name for the restored table.
6. Initiate the restore process.

### Common Issues
### DynamoDB throttling errors
*   **Diagnosis**: Monitor `ThrottledRequests` metric. If using `PAY_PER_REQUEST`, this indicates sudden spikes in traffic exceeding internal limits. If using `PROVISIONED`, it means RCU/WCU limits are reached.
*   **Resolution**: For `PAY_PER_REQUEST`, optimize application access patterns and ensure efficient querying. If using `PROVISIONED`, increase RCU/WCU or configure auto-scaling. Ensure efficient data modeling and query design to minimize read/write operations.

### High latency
*   **Diagnosis**: Monitor `SuccessfulRequestLatency`. Investigate inefficient queries, hot partitions, or network issues. Check for large item sizes.
*   **Resolution**: Optimize queries, ensure proper key design to distribute load evenly, consider data denormalization if appropriate, and ensure the client application has a stable network connection.

## Rollback Procedure
1. Revert the IaC commit that modified the DynamoDB table configuration.
2. Apply the reverted IaC using `terraform apply` or equivalent.
3. If the table was accidentally deleted, restore it from a PITR backup using the procedure outlined above.
