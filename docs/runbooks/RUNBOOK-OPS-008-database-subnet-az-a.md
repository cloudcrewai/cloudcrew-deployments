# Runbook: Database Subnet AZ-A

## Overview
Database Subnet AZ-A is a private network segment within Availability Zone A specifically designated for hosting database instances. It ensures that databases are isolated and not directly exposed to the internet.

## Prerequisites
- AWS CLI with permissions to view and manage subnets and route tables.
- An existing VPC configured for high availability.

## Architecture
This subnet is located in Availability Zone A and uses the CIDR block 10.0.21.0/24. It is configured as a private subnet, meaning it does not have a direct route to the internet gateway. Route tables ensure that database instances within this subnet can only communicate with specific application tiers or other authorized resources.

## Operations

### Scaling
1. Additional database subnets can be provisioned in AZ-A or other Availability Zones to support more database instances or to provide further segmentation.
2. The CIDR block can be expanded if necessary, following the VPC's IP address management strategy.

### Monitoring
Monitor the IP address utilization of the subnet to prevent exhaustion. VPC Flow Logs can be enabled to audit access to and from the database subnet. Focus monitoring on the health and performance of the database instances within this subnet.

### Backup & Recovery
Database subnets are network constructs and are not backed up. Their configuration is managed through Infrastructure as Code. If deleted, they can be recreated using the IaC.

### Common Issues
### Database Instance Unreachable
Diagnosis: Application instances cannot connect to database instances within this subnet.
Resolution: Verify that the route tables associated with the application subnets correctly point to the database subnet or its relevant endpoints. Check Network Access Control Lists (NACLs) and Security Groups associated with both the application and database instances to ensure traffic is permitted. Confirm the database instance itself is running and accessible.

## Rollback Procedure
1. Revert the Infrastructure as Code (IaC) changes related to the database subnet.
2. Apply the reverted IaC configuration.
3. Verify that database instances within the subnet are accessible by authorized resources.
