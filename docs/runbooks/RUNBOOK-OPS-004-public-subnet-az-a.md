# Runbook: Public Subnet AZ-A

## Overview
The Public Subnet in Availability Zone A is configured to host resources that require direct internet access, such as NAT Gateways. It is part of the IoT VPC.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Network administration knowledge

## Architecture
Located in Availability Zone A with CIDR block 10.0.1.0/24. It contains a route to the Internet Gateway, allowing resources within this subnet to communicate directly with the internet. This subnet hosts the NAT Gateway for AZ-A.

## Operations

### Scaling
Subnet scaling is managed by CIDR block allocation. To expand the IP address range within this AZ, a new CIDR block can be associated with the VPC and then carved out for this subnet.

### Monitoring
Key metrics: Subnet IP address utilization. Monitor traffic through the Internet Gateway associated with this subnet's route table. Monitor the health and availability of resources deployed within this subnet (e.g., NAT Gateway).

### Backup & Recovery
Subnet configurations are managed via Infrastructure as Code (IaC). Recovery involves re-deploying the subnet configuration from the IaC repository.

### Common Issues
### IP address exhaustion
**Diagnosis**: Monitor the number of available IP addresses within the subnet using network tools or by checking associated resource counts.
**Resolution**: Expand the subnet's CIDR block if possible, or create a new subnet with a different CIDR range.

## Rollback Procedure
1. Revert the IaC commit that modified the public subnet configuration.
2. Execute 'terraform apply' to redeploy the previous state.
3. Verify network reachability for resources within the subnet.
