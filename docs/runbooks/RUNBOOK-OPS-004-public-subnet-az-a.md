# Runbook: Public Subnet AZ-A

## Overview
The public subnet in Availability Zone A is a segment of the VPC network that has a route to the Internet Gateway, allowing resources within it to be directly accessible from the internet.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Associated route table with an Internet Gateway route

## Architecture
Located in Availability Zone A with CIDR block 10.0.1.0/24. Resources like NAT Gateways and potentially internet-facing Load Balancers are placed here. It is associated with a route table directing internet-bound traffic to the Internet Gateway.

## Operations

### Scaling
The subnet's CIDR block is fixed. To scale the number of resources, additional public subnets can be created in the same or different AZs, provided the VPC CIDR allows. This requires updating route tables and potentially load balancer configurations.

### Monitoring
Monitor IP address utilization within the subnet to ensure sufficient capacity. Key metrics include `AvailableIpAddressCount`. Set alarms for low available IP addresses.

### Backup & Recovery
Subnets are logical constructs within a VPC. Recovery involves ensuring the VPC and its associated route tables are correctly defined in IaC. If a subnet is inadvertently deleted, it can be recreated using the IaC definitions.

### Common Issues
### Resource inaccessible from the internet
**Diagnosis**: Verify the subnet's route table is correctly associated and has a route to the Internet Gateway. Check Security Group and Network ACL rules for the resource.
**Resolution**: Correct the route table association or rules. Ensure the resource's Security Group allows inbound traffic from `0.0.0.0/0` on the necessary ports.

## Rollback Procedure
1. Revert the IaC commit that modified the subnet or its associated route table.
2. Run `terraform apply` to restore the previous configuration.
3. Verify network accessibility.
