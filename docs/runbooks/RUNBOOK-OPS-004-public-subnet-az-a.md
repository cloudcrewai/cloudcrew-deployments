# Runbook: Public Subnet AZ-A

## Overview
Public Subnet AZ-A provides network space within Availability Zone A for resources that require direct internet access, such as NAT Gateways. It is associated with a route table that directs internet-bound traffic to the Internet Gateway.

## Prerequisites
- AWS CLI with permissions to view and manage subnets and route tables.
- An existing VPC with internet gateway attached.

## Architecture
Located in Availability Zone A, this subnet uses the CIDR block 10.0.1.0/24. It is designed to host resources like NAT Gateways, which need to be accessible from the internet to perform their function. It is associated with a route table that has a default route to the Internet Gateway.

## Operations

### Scaling
1. Additional public subnets can be created in AZ-A or other Availability Zones to segment resources further or to provide more granular network control.
2. The CIDR block of the public subnet can be modified if necessary, but this requires careful planning to avoid IP conflicts with other subnets within the VPC.

### Monitoring
Monitor the IP address utilization of the subnet to prevent exhaustion. VPC Flow Logs can be enabled for this subnet to track inbound and outbound traffic patterns. No specific CloudWatch alarms are directly configured for the subnet itself.

### Backup & Recovery
Subnets are configuration elements within a VPC and are not directly backed up. Their state is maintained by AWS and defined within the Infrastructure as Code. If a subnet is inadvertently deleted, it can be recreated using the IaC.

### Common Issues
### IP Address Exhaustion
Diagnosis: The subnet has run out of available IP addresses.
Resolution: Assess if resources within the subnet can be moved to another subnet with more available IPs. If necessary, expand the subnet's CIDR block or create a new, larger subnet. Ensure proper resource lifecycle management to release unused IPs.

## Rollback Procedure
1. Revert the Infrastructure as Code (IaC) changes related to the public subnet.
2. Apply the reverted IaC configuration.
3. Verify that resources within the subnet maintain their network connectivity.
