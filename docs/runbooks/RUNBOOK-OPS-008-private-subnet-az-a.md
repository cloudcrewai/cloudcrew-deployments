# Runbook: Private Subnet AZ-A

## Overview
A private subnet is a range of IP addresses in your VPC that is not directly accessible from the internet. This subnet resides in Availability Zone 'a' and has a CIDR block of '10.0.3.0/24'. It is used for resources like application servers and databases that should not be exposed publicly.

## Prerequisites
- AWS CLI configured with appropriate permissions.
- IAM user/role with VPC read/write access.

## Architecture
Part of the 'App VPC', this subnet is configured with a route table that directs outbound internet traffic through the 'NAT Gateway AZ-A'. It hosts backend application components and potentially databases.

## Operations

### Scaling
Subnet capacity is determined by the CIDR block size. To 'scale' subnet capacity, you would typically create additional subnets or adjust CIDR ranges if feasible and planned.

### Monitoring
Monitor Network In/Out for resources within this subnet. Track traffic flow through associated route tables.

### Backup & Recovery
Subnets are network constructs within a VPC and are not directly backed up. Their configuration is part of the VPC's state. Recovery involves recreating the subnet with the same CIDR and route table associations if the VPC itself needs to be re-established.

### Common Issues
### Instances in this subnet cannot reach the internet
- **Diagnosis**: Verify the subnet's route table is configured to route `0.0.0.0/0` traffic to the 'NAT Gateway AZ-A'. Check the status of the NAT Gateway and ensure it has an associated Elastic IP.
- **Resolution**: Correct route table entries. Ensure NAT Gateway is healthy and accessible.

## Rollback Procedure
1. Revert IaC changes related to the private subnet's configuration (CIDR, route table association).
2. Apply the reverted IaC.
3. Verify network connectivity.
