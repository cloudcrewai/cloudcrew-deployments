# Runbook: App VPC

## Overview
The App VPC (Virtual Private Cloud) serves as the isolated network environment for the AWS resources. It defines the IP address space and network configuration, enabling secure and controlled communication between deployed services.

## Prerequisites
- AWS CLI with permissions to describe VPCs and related networking components.
- AWS Management Console access.

## Architecture
The VPC utilizes a CIDR block of 10.0.0.0/16, encompassing multiple Availability Zones. It is configured with public and private subnets, Internet Gateway, and NAT Gateways to manage inbound and outbound network traffic.

## Operations

### Scaling
VPC scaling is primarily achieved by adding more subnets across Availability Zones to accommodate growth and improve availability. The CIDR block can be expanded if necessary, though this is a significant architectural change.

### Monitoring
Key CloudWatch metrics related to VPC components:
- VPC Flow Logs: Monitor network traffic patterns, identify security threats, and troubleshoot connectivity issues.
- NAT Gateway metrics (as detailed in respective runbooks): Monitor traffic volume and errors.
- Subnet metrics: Indirectly monitored via resources deployed within them.

Alarm thresholds should be set based on expected traffic patterns and security policies.

### Backup & Recovery
VPC configurations are managed via Infrastructure-as-Code (IaC) and are inherently version-controlled. Recovery involves reapplying the IaC definition. There are no point-in-time backups for VPC configurations themselves.

### Common Issues
### IP Address Exhaustion
**Diagnosis**: Monitor the usage of CIDR blocks within subnets. If a subnet's CIDR block is nearing exhaustion, it may indicate a need for more IP addresses.
**Resolution**: Add new subnets with sufficient CIDR space, or in extreme cases, consider VPC peering or a larger VPC CIDR block if the initial allocation was insufficient. Ensure subnet CIDR blocks are appropriately sized from the outset.

### Connectivity Issues
**Diagnosis**: Utilize VPC Flow Logs to trace network traffic. Check route tables, Network ACLs (NACLs), and Security Groups to ensure traffic is permitted between resources.
**Resolution**: Systematically review network configurations: route tables for correct destination/target paths, NACLs for subnet-level rules, and Security Groups for instance-level rules. Use tools like VPC Reachability Analyzer.

## Rollback Procedure
1. Revert the IaC commit that defines the VPC configuration.
2. Apply the reverted IaC (e.g., `terraform apply`).
3. Verify that the VPC and its associated resources are in the desired rolled-back state.
