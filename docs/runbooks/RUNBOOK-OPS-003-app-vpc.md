# Runbook: App VPC

## Overview
The Virtual Private Cloud (VPC) provides a logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define. The 'App VPC' is the network foundation for the 'three-tier-web-app'.

## Prerequisites
- AWS CLI configured with appropriate permissions.
- IAM user/role with VPC read/write access.

## Architecture
Defines the network space for the application with a CIDR block of '10.0.0.0/16'. It includes public and private subnets across two Availability Zones ('a' and 'b'), an Internet Gateway, and NAT Gateways for outbound internet access from private subnets.

## Operations

### Scaling
VPC resources like CIDR blocks and subnets are typically static configurations. Scaling is achieved by adding more resources within the existing VPC structure (e.g., new subnets, EC2 instances, containers).

### Monitoring
Monitor network traffic in and out of the VPC. Key metrics include Network In/Out for NAT Gateways, VPC Flow Logs for traffic analysis, and Subnet traffic metrics.

### Backup & Recovery
VPC configurations are persisted in AWS. Backup involves exporting the VPC configuration (e.g., via AWS Config or manual documentation). Recovery typically involves recreating the VPC and its associated resources based on the exported configuration or IaC.

### Common Issues
### Connectivity issues between subnets
- **Diagnosis**: Review VPC route tables associated with public and private subnets. Ensure security group and Network ACL rules permit traffic.
- **Resolution**: Correct route table entries to ensure traffic can flow to the correct destinations (e.g., NAT Gateway for outbound from private, IGW for inbound to public). Adjust Security Groups and NACLs as needed.

### Inability to reach the internet from private subnets
- **Diagnosis**: Verify NAT Gateway health and status. Check route tables in private subnets to ensure they point to the NAT Gateway. Confirm Elastic IPs are associated with NAT Gateways.
- **Resolution**: Ensure NAT Gateways are deployed in public subnets and correctly configured. Verify route table association.

## Rollback Procedure
1. Revert IaC changes related to the VPC configuration.
2. Apply the reverted IaC.
3. Verify network connectivity and resource accessibility.
