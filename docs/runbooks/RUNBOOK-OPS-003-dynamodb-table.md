# Runbook: DynamoDB Table

## Overview
The DynamoDB table serves as the primary data store for the serverless API, providing a highly available and scalable NoSQL database solution.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM permissions for Lambda functions to perform CRUD operations on the DynamoDB table.
- Knowledge of the table's primary key (`id`).

## Architecture
A single DynamoDB table configured for Pay-Per-Request billing mode. Point-in-Time Recovery (PITR) and Server-Side Encryption (SSE) using a KMS key are enabled for data durability and security.

## Operations

### Scaling
DynamoDB in Pay-Per-Request mode automatically scales throughput based on demand. Monitor consumed read/write capacity units to understand usage patterns.

### Monitoring
Key metrics:
- `ConsumedReadCapacityUnits`: Monitor for spikes that might indicate performance bottlenecks or unexpected load.
- `ConsumedWriteCapacityUnits`: Similar to read capacity, monitor for high usage.
- `SuccessfulRequestLatency`: Average latency for read and write operations. Alarm if latency increases significantly.
- `ThrottledRequests`: Number of requests throttled due to exceeding provisioned capacity (less relevant for PAY_PER_REQUEST but good to monitor for underlying limits).

### Backup & Recovery
Point-in-Time Recovery (PITR) is enabled, allowing restoration to any second in the preceding 35 days. Restore procedure involves initiating a restore operation from the AWS Management Console or CLI, specifying a recovery point in time.

### Common Issues
### High latency or throttling
- **Diagnosis**: Check `ConsumedReadCapacityUnits`, `ConsumedWriteCapacityUnits`, and `ThrottledRequests` metrics. Identify the source of the increased traffic/load.
- **Resolution**: Optimize application queries for efficiency. If consistently high, consider migrating to provisioned capacity mode with adequate provisioned throughput, or analyze application logic for inefficiencies.

## Rollback Procedure
1. Revert Infrastructure as Code (Terraform) changes related to the DynamoDB table configuration.
2. Apply the reverted configuration using `terraform apply`.
3. If a data restore is needed, use the Point-in-Time Recovery feature to restore the table to a previous state.
