# Runbook: Public Subnet AZ-B

## Overview
The public subnet in Availability Zone B is a segment of the VPC's IP address space intended for resources that require direct internet access, such as Application Load Balancers, ensuring high availability across AZs.

## Prerequisites
- AWS CLI configured with appropriate permissions
- VPC must exist
- Route table associated with this subnet must have a route to the Internet Gateway

## Architecture
Located in AZ-B. Resources like ALBs are placed here, mirroring AZ-A for redundancy. It is routable to the internet via the Internet Gateway.

## Operations

### Scaling
Subnets are network constructs and do not scale in the traditional sense. Scaling is achieved by adding more resources (e.g., ALB instances) within the subnet or by adding additional subnets.

### Monitoring
Key metrics: VPC Flow Logs to monitor traffic entering/leaving the subnet. Monitor resource availability (e.g., ALB health checks) within the subnet.

### Backup & Recovery
Subnets are part of the VPC configuration. Recovery involves re-deploying the VPC and its subnet definitions from IaC.

### Common Issues
### Resources in public subnet AZ-B are unreachable from the internet
**Diagnosis**: Verify route table for this subnet has a route to IGW for `0.0.0.0/0`. Check Network ACLs and Security Groups applied to resources within the subnet. Ensure the resource itself is running and healthy.
**Resolution**: Correct route table, NACLs, or Security Groups. Troubleshoot the resource's operational status.

## Rollback Procedure
1. Revert the IaC commit that modified the public subnet configuration.
2. Apply the changes using the IaC tool.
3. Verify resource accessibility from the internet.
