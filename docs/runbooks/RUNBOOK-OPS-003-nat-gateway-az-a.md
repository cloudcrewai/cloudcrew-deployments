# Runbook: NAT Gateway AZ-A

## Overview
The NAT Gateway in Availability Zone A enables instances in private subnets within AZ-A to connect to the internet or other AWS services while preventing inbound connections initiated from the internet.

## Prerequisites
- AWS CLI configured with appropriate credentials.
- IAM permissions to describe NAT Gateways, Elastic IPs, and route tables.
- An Elastic IP address allocated.

## Architecture
Deployed in the public subnet of Availability Zone A. A route table associated with the private subnet(s) in AZ-A directs outbound internet traffic to this NAT Gateway.

## Operations

### Scaling
NAT Gateways are designed for high availability and scale automatically. If higher throughput is consistently needed, consider provisioning additional NAT Gateways and configuring routing appropriately, though this is typically managed via IaC.

### Monitoring
Monitor CloudWatch metrics for NAT Gateway: `BytesInFromSource`, `BytesOutToDestination`, `ActiveConnectionCount`, `PacketsDropCount`. High `PacketsDropCount` indicates potential network saturation.

### Backup & Recovery
NAT Gateways are managed resources. Configuration is part of the VPC's Infrastructure as Code. Redeploy the IaC to recreate the NAT Gateway if it's accidentally deleted.

### Common Issues
### Instances in private subnet AZ-A cannot access the internet
1. Verify the NAT Gateway is in a 'Ready' state.
2. Check the route table associated with the private subnet AZ-A. Ensure a default route (0.0.0.0/0) points to the NAT Gateway.
3. Confirm the Elastic IP associated with the NAT Gateway is correctly configured.
4. Check security groups and Network ACLs for both the instances and the NAT Gateway's subnet.

## Rollback Procedure
1. Revert the Infrastructure as Code commit that modified or removed the NAT Gateway AZ-A.
2. Execute the IaC apply command.
3. Verify instances in private subnet AZ-A can access the internet.
