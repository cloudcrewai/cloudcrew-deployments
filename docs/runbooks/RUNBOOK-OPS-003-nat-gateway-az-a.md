# Runbook: NAT Gateway AZ-A

## Overview
The NAT Gateway in Availability Zone A allows instances in private subnets within AZ-A to connect to the internet or other AWS services, but prevents the internet from initiating connections with those instances.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Public subnet in AZ-A with an Elastic IP association
- Route table associated with private subnets in AZ-A pointing to this NAT Gateway

## Architecture
Deployed in the public subnet of AZ-A. Resources in the private subnet of AZ-A will route outbound traffic through this NAT Gateway.

## Operations

### Scaling
NAT Gateways are managed AWS services that scale automatically. No manual scaling configuration is necessary. Bandwidth limits are per NAT Gateway. For higher throughput, multiple NAT Gateways can be deployed across AZs.

### Monitoring
Key metrics: BytesInFromSource, BytesOutToDestination, PacketsInFromSource, PacketsOutToDestination (via CloudWatch metrics for the associated Elastic Network Interface). Monitor for high latency or dropped packets. Check associated Elastic IP health.

### Backup & Recovery
NAT Gateways are managed AWS resources. Recovery is through re-deployment of the NAT Gateway and its associated Elastic IP via IaC. Ensure the Elastic IP is correctly associated.

### Common Issues
### Instances in private subnet AZ-A cannot reach the internet
**Diagnosis**: Verify route table for private subnet AZ-A directs `0.0.0.0/0` traffic to the NAT Gateway. Check CloudWatch metrics for high traffic or errors on the NAT Gateway's ENI. Ensure the NAT Gateway has a valid Elastic IP.
**Resolution**: Correct route table entries. Investigate traffic volume and consider scaling to multiple NAT Gateways if necessary. Confirm EIP association.

## Rollback Procedure
1. Revert the IaC commit that modified the NAT Gateway configuration.
2. Apply the changes using the IaC tool.
3. Verify outbound internet connectivity from private subnets in AZ-A.
