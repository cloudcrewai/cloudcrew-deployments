# Runbook: Internet Gateway

## Overview
The Internet Gateway (IGW) provides a pathway for resources in public subnets to communicate with the internet. It enables inbound traffic from the internet to reach the VPC.

## Prerequisites
- AWS CLI configured with appropriate permissions.
- IAM permissions to describe VPCs and Internet Gateways.

## Architecture
Attached directly to the 'App VPC', the IGW allows traffic to flow between the VPC and the public internet. It is essential for resources in public subnets that need direct internet access, such as Application Load Balancers.

## Operations

### Scaling
Internet Gateways are managed services and do not require manual scaling. AWS handles the scaling and availability of the IGW automatically.

### Monitoring
Monitor metrics related to traffic flow and potential errors through VPC Flow Logs. High traffic volumes indicate active internet communication.

### Backup & Recovery
The Internet Gateway is a resilient AWS managed service. In the event of an issue, AWS manages its availability. Configuration is part of the main VPC IaC.

### Common Issues
### Inability to Reach Internet from Public Subnet
- **Diagnosis**: Ensure the IGW is attached to the VPC and that the route table for the public subnet has a route to the IGW (0.0.0.0/0 -> igw-id).
- **Resolution**: Attach the IGW if missing, and update the route table accordingly.

## Rollback Procedure
1. Revert the IaC commit that modified the Internet Gateway.
2. Apply the changes using the IaC tool (e.g., `terraform apply`).
3. Verify internet connectivity for resources in public subnets.
