# Runbook: Internet Gateway

## Overview
The Internet Gateway (IGW) provides a connection point between the VPC and the internet, allowing resources in public subnets to access the internet and be accessed from the internet.

## Prerequisites
- AWS CLI configured with appropriate permissions
- VPC must exist

## Architecture
Attached to the 'App VPC'. Resources in public subnets are routable via the IGW. No direct scaling configuration; it's a static attachment.

## Operations

### Scaling
The Internet Gateway is a managed AWS resource. It scales automatically based on demand. No manual scaling actions are required.

### Monitoring
Key metrics: None directly exposed for IGW. Monitor network traffic and application availability for services relying on IGW access. Check VPC Flow Logs for traffic patterns.

### Backup & Recovery
The Internet Gateway is a managed AWS resource. There is no backup or recovery procedure beyond re-attaching it to the VPC if it were ever detached (which is a manual administrative action).

### Common Issues
### Inability to reach the internet from public subnets
**Diagnosis**: Verify that the route table associated with the public subnet has a route to the Internet Gateway for `0.0.0.0/0`. Check security groups and NACLs.
**Resolution**: Update route tables, security groups, or NACLs as required.

## Rollback Procedure
1. Revert the IaC commit that modified the Internet Gateway attachment.
2. Apply the changes using the IaC tool.
3. Verify internet connectivity.
