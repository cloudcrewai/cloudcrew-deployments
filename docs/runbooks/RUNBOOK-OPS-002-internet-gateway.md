# Runbook: Internet Gateway

## Overview
The Internet Gateway (IGW) allows communication between resources within the VPC and the public internet. It is essential for services that need to be accessed from the internet or require outbound internet connectivity.

## Prerequisites
- AWS CLI configured with appropriate permissions
- VPC with an associated Internet Gateway

## Architecture
The Internet Gateway is attached to the 'App VPC' (10.0.0.0/16). It enables routing traffic from public subnets to the internet via routes defined in the VPC's route tables.

## Operations

### Scaling
The Internet Gateway is a highly available AWS managed service and does not require manual scaling. Its capacity scales automatically to meet demand.

### Monitoring
Monitor VPC Flow Logs for traffic patterns and anomalies. While IGW itself doesn't have direct metrics, associated network traffic can be monitored. Check for Network ACL or Security Group rule changes that might affect connectivity.

### Backup & Recovery
Internet Gateways are managed by AWS and are inherently redundant. Recovery is automatic in case of failures. Configuration changes are managed via IaC.

### Common Issues
### Inability to reach the internet from public subnets
- **Diagnosis**: Verify the Internet Gateway is attached to the VPC. Check route tables for public subnets to ensure they have a default route (0.0.0.0/0) pointing to the Internet Gateway. Ensure Network ACLs and Security Groups associated with resources in public subnets allow outbound traffic.
- **Resolution**: Attach the IGW if missing. Add the default route to the public subnet route tables targeting the IGW. Adjust Network ACLs and Security Groups as needed.

## Rollback Procedure
1. Revert the Infrastructure as Code (IaC) changes related to the Internet Gateway.
2. Apply the reverted IaC using the deployment tool (e.g., `terraform apply`).
3. Verify internet connectivity for resources in public subnets.
