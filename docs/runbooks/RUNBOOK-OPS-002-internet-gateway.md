# Runbook: Internet Gateway

## Overview
The Internet Gateway (IGW) allows communication between the VPC and the internet. It enables resources in public subnets to access the internet and be accessed from the internet.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM user or role with EC2 network management privileges

## Architecture
The IGW is attached to the App VPC, enabling internet connectivity for resources within the VPC that have routes pointing to it, typically resources in public subnets.

## Operations

### Scaling
The Internet Gateway is a highly available and horizontally scaled AWS service. No manual scaling is required. Ensure sufficient IP addresses are available in associated subnets if many resources need internet access.

### Monitoring
Monitor CloudWatch metrics for the VPC attachment status and any traffic anomalies. Examine VPC Flow Logs for traffic patterns to and from the internet.

### Backup & Recovery
The Internet Gateway configuration is managed via Infrastructure as Code (IaC). Recovery involves re-applying the IaC configurations. It is a stateless resource and does not require traditional backups.

### Common Issues
### No internet access for public resources
Diagnosis: Verify the IGW is attached to the VPC. Check route tables for public subnets to ensure they have a route to the IGW (0.0.0.0/0).
Resolution: Ensure IGW is attached and route table is correctly configured. Verify Security Group and Network ACL rules permit traffic.

## Rollback Procedure
1. Revert the IaC commit that modified the Internet Gateway configuration.
2. Apply the reverted IaC configuration.
3. Verify internet connectivity for public resources.
