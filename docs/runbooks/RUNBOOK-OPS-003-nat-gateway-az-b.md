# Runbook: NAT Gateway AZ-B

## Overview
The NAT Gateway in Availability Zone B enables instances in private subnets within AZ-B to connect to the internet or other AWS services while preventing inbound connections initiated from the internet.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Elastic IP address associated with the NAT Gateway
- Route table configured to direct traffic through the NAT Gateway.

## Architecture
Deployed in the public subnet of Availability Zone B. Associated with an Elastic IP address. A route table in the private subnet(s) of AZ-B directs internet-bound traffic (0.0.0.0/0) to this NAT Gateway.

## Operations

### Scaling
NAT Gateway scaling is managed by AWS. To handle increased traffic, consider deploying additional NAT Gateways in different Availability Zones and updating route tables accordingly, or utilizing VPC endpoints for services that support them.

### Monitoring
Key metrics: `BytesInFromSource`, `BytesOutToDestination`, `PacketsInFromSource`, `PacketsOutToDestination`. Monitor `ActiveConnectionCount`. High `ErrorPortAllocation` indicates potential issues.

### Backup & Recovery
NAT Gateways are managed services; backups are not applicable. In case of failure, AWS automatically provisions a replacement. Ensure Elastic IPs are correctly configured for seamless failover.

### Common Issues
### Internet connectivity issues from private subnets
**Diagnosis**: Check CloudWatch metrics for `ErrorPortAllocation`. Verify the route table associated with the private subnet correctly points 0.0.0.0/0 to the NAT Gateway.
**Resolution**: Ensure sufficient available ephemeral ports. If persistent, consider if traffic patterns exceed NAT Gateway capacity.

## Rollback Procedure
1. Revert the IaC commit that modified the NAT Gateway or associated route tables.
2. Execute 'terraform apply'.
3. Verify outbound internet connectivity from private subnets.
