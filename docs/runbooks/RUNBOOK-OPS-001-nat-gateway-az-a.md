# Runbook: NAT Gateway AZ-A

## Overview
The NAT Gateway in Availability Zone A facilitates outbound internet connectivity for resources within private subnets. It enables instances in private subnets to initiate connections to the internet or other AWS services while preventing inbound connections from the internet.

## Prerequisites
- AWS CLI configured with appropriate IAM permissions for EC2 and VPC actions.
- Access to the AWS Management Console.

## Architecture
The NAT Gateway AZ-A is deployed in the public subnet of Availability Zone A and is associated with an Elastic IP address. Route tables for private subnets in AZ-A direct internet-bound traffic to this NAT Gateway.

## Operations

### Scaling
1. NAT Gateways are regional resources, but their availability is tied to the Availability Zone they are deployed in. To scale availability, ensure NAT Gateways are deployed in multiple AZs, as configured in this setup with NAT Gateway AZ-B.
2. Network throughput for NAT Gateways scales automatically based on demand.

### Monitoring
Key CloudWatch metrics to monitor:
- `BytesInFromSource`: Incoming traffic from private subnets.
- `BytesOutToDestination`: Outgoing traffic to the internet.
- `ActiveConnectionCount`: Number of active connections.
- `ErrorPortAllocation`: Indicates issues with port allocation, a potential bottleneck.

Recommended alarm thresholds:
- `ActiveConnectionCount` > 90% of the limit (e.g., > 50,000 for a standard NAT Gateway).
- `ErrorPortAllocation` > 0.

### Backup & Recovery
NAT Gateways are managed AWS services and do not require traditional backups. High availability is achieved by deploying them across multiple Availability Zones. In the event of an Availability Zone failure, traffic will automatically be rerouted to the NAT Gateway in another AZ.

### Common Issues
### NAT Gateway Unreachable
**Diagnosis**: Check if the NAT Gateway's Elastic IP is correctly associated and if the route table for the private subnet points to the correct NAT Gateway ID. Ensure the NAT Gateway is in a public subnet with a route to the Internet Gateway.
**Resolution**: Verify NAT Gateway status in the VPC console. Correct route table configurations and re-associate EIP if necessary.

### Slow Internet Connectivity from Private Subnets
**Diagnosis**: Monitor `BytesInFromSource` and `BytesOutToDestination` for high utilization. Check for other potential network bottlenecks in the VPC or the destination service.
**Resolution**: Consider increasing NAT Gateway capacity if available, or investigate if the bottleneck lies elsewhere in the network path. Distributing traffic across multiple NAT Gateways in different AZs can also help.

## Rollback Procedure
1. Revert the IaC commit that defines the NAT Gateway resource.
2. Apply the reverted IaC configuration (e.g., `terraform apply`).
3. Verify that the NAT Gateway is no longer present or in the desired state.
