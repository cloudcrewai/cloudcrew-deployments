# Runbook: App VPC

## Overview
The App VPC provides a logically isolated network environment within AWS for the application. It defines the IP address space and network boundaries for all resources within the production environment.

## Prerequisites
AWS CLI configured with appropriate permissions to view VPC and subnet configurations.

## Architecture
The VPC uses a CIDR block of 10.0.0.0/16. It is configured with DNS hostnames and support enabled. Internet Gateway is attached to allow communication with the internet. NAT Gateways are deployed in each Availability Zone (AZ-A and AZ-B) within public subnets to provide outbound internet access for resources in private subnets. Public subnets (10.0.1.0/24 in AZ-A, 10.0.2.0/24 in AZ-B) host resources requiring direct internet access or public endpoints. Private application subnets (10.0.11.0/24 in AZ-A, 10.0.12.0/24 in AZ-B) are intended for application-tier resources like ECS tasks.

## Operations

### Scaling
The VPC itself does not scale in the traditional sense. Scaling is managed by the resources deployed within it (e.g., subnets, NAT gateways, and the services they host). If more IP address space is required, a new VPC or VPC peering may be necessary. NAT Gateway scaling is handled automatically by AWS. Subnet CIDR blocks can be expanded if within the VPC's overall CIDR, or new subnets can be added.

### Monitoring
Key metrics to monitor include: VPC Flow Logs for network traffic analysis, NAT Gateway metrics (e.g., ActiveConnectionCount, BytesInFromSource, BytesOutToSource) for connection and data transfer monitoring, and Subnet metrics for IP address utilization.

### Backup & Recovery
VPC configurations are managed via Infrastructure as Code (IaC) and are inherently version-controlled. In the event of a catastrophic failure, the VPC can be recreated by applying the IaC definitions. Resource configurations within the VPC (e.g., Security Groups, Route Tables) should also be backed by IaC.

### Common Issues
### Connectivity issues to the internet from private subnets
- **Diagnosis**: Verify NAT Gateway is functioning and routing is correctly configured in the private subnet's route table to point internet-bound traffic (0.0.0.0/0) to the NAT Gateway. Check Security Group and Network ACL rules.
- **Resolution**: Ensure NAT Gateway has an Elastic IP and is associated with a public subnet. Update route tables as needed. Review Security Group and NACL configurations for any blocked outbound traffic.

### IP address exhaustion in a subnet
- **Diagnosis**: Monitor subnet IP address utilization. Check for a large number of resources launched in a single subnet.
- **Resolution**: Consider distributing resources across multiple subnets or Availability Zones. If necessary, expand the subnet CIDR block (if within VPC limits) or create new subnets.

## Rollback Procedure
1. Revert the Infrastructure as Code (IaC) commit that modified the VPC configuration.
2. Apply the reverted IaC (e.g., `terraform apply`).
3. Verify that network connectivity and resource accessibility are restored as expected.
