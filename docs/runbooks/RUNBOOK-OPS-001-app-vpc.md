# Runbook: App VPC

## Overview
The App VPC provides a logically isolated network within AWS for the three-tier web application. It encompasses public and private subnets across multiple Availability Zones, facilitating a secure and highly available infrastructure.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Access to VPC configuration in AWS Console

## Architecture
Consists of a /16 CIDR block (10.0.0.0/16) with public subnets for internet-facing resources and private subnets for backend services. Internet Gateway is attached, and NAT Gateways are provisioned in each Availability Zone for outbound internet access from private subnets.

## Operations

### Scaling
VPC CIDR blocks and subnet sizes are generally static and defined during initial setup. Scaling typically involves adding new subnets within the existing VPC CIDR range or expanding CIDR blocks if necessary, which requires careful planning to avoid IP address exhaustion.

### Monitoring
Key metrics to monitor include VPC Flow Logs for network traffic analysis, Subnet IP address utilization, and NAT Gateway Elastic IP Address utilization. Alarms should be set for low available IP addresses in subnets and high NAT Gateway utilization.

### Backup & Recovery
VPC configurations are managed via Infrastructure as Code (IaC). Recovery involves re-deploying the VPC configuration using the IaC definitions. Data backups are handled by individual services (e.g., RDS, ElastiCache) not the VPC itself.

### Common Issues
### Subnet IP exhaustion
**Diagnosis**: CloudWatch alarm on subnet IP availability triggers, or direct observation in AWS Console.
**Resolution**: Plan and implement VPC CIDR expansion or migrate resources to newly created subnets with sufficient IP space. This requires careful coordination to avoid overlapping IPs.

## Rollback Procedure
1. Revert the IaC commit that modified the VPC configuration.
2. Run `terraform apply` to revert the changes.
3. Verify network connectivity and resource accessibility.
