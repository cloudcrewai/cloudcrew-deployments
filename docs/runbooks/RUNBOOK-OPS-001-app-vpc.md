# Runbook: App VPC

## Overview
The App VPC provides a private network space for AWS resources, isolating them from the public internet and enabling controlled network access.

## Prerequisites
- AWS CLI configured with appropriate credentials.
- IAM permissions to describe VPC, Subnets, Route Tables, and NAT Gateways.

## Architecture
A Class C /16 CIDR block (10.0.0.0/16) spanning across two Availability Zones (a and b). It contains public subnets for internet-facing resources and private subnets for backend services. Internet Gateway provides access to the internet, and NAT Gateways in each AZ allow instances in private subnets to initiate outbound internet connections.

## Operations

### Scaling
VPC scaling is not applicable as it's a foundational network resource. Subnet CIDR ranges can be extended if the number of resources exceeds current capacity, requiring a change in `var.public_subnet_cidrs` and `var.private_subnet_cidrs`.

### Monitoring
Key metrics include VPC Flow Logs for traffic analysis, and Subnet utilization metrics. Monitor Route Table entries for unexpected routes.

### Backup & Recovery
VPC configuration is declarative and managed by Infrastructure as Code. In case of accidental deletion, redeploy the VPC configuration using the IaC pipeline.

### Common Issues
### No internet connectivity from private subnets
Ensure NAT Gateways are healthy and associated with Elastic IPs. Verify route tables in private subnets correctly point internet-bound traffic (0.0.0.0/0) to the NAT Gateways.

### Unreachable resources within the VPC
Check security groups and Network ACLs associated with the resources and subnets to ensure traffic is allowed. Verify route table entries for internal traffic.

## Rollback Procedure
1. Revert the Infrastructure as Code commit that modified the VPC configuration.
2. Execute the IaC apply command.
3. Verify network connectivity and resource accessibility within the VPC.
