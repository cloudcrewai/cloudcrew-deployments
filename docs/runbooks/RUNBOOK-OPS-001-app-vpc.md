# Runbook: App VPC

## Overview
The App VPC serves as the foundational network boundary for the three-tier web application. It isolates AWS resources and defines the network space using a specified CIDR block.

## Prerequisites
- AWS CLI configured with appropriate permissions.
- IAM permissions to describe VPCs and associated resources.

## Architecture
The VPC spans multiple Availability Zones (AZs) to ensure high availability. It contains public and private subnets, along with associated Internet Gateways and NAT Gateways for controlled internet access.

## Operations

### Scaling
VPC scaling is primarily managed by adjusting CIDR blocks and subnet configurations. This is typically a manual process handled during initial setup or significant architectural changes, not a routine operational task.

### Monitoring
Key metrics to monitor include VPC Flow Logs for network traffic analysis, and resource counts within the VPC. Alarms can be set for unusual traffic patterns or resource exhaustion.

### Backup & Recovery
VPC configurations are managed via Infrastructure-as-Code. In case of accidental deletion, the VPC can be recreated by applying the IaC. Data within resources like RDS or S3 have their own backup and recovery strategies.

### Common Issues
### Network Connectivity Issues
- **Diagnosis**: Check route tables, NACLs, and security groups associated with affected resources.
- **Resolution**: Ensure correct routing to IGW/NAT Gateways and that security group/NACL rules permit traffic.

### IP Address Exhaustion
- **Diagnosis**: Monitor subnet CIDR utilization. Inadequate planning can lead to exhaustion.
- **Resolution**: Requires VPC redesign with larger CIDR blocks or additional VPCs, managed via IaC.

## Rollback Procedure
1. Revert the IaC commit that modified the VPC configuration.
2. Apply the changes using the IaC tool (e.g., `terraform apply`).
3. Verify network connectivity and resource accessibility.
