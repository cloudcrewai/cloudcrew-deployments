# Runbook: App VPC

## Overview
The App VPC provides a private network space for AWS resources, isolating them from the public internet. It is configured with multiple Availability Zones for high availability and contains public, private, and database subnets.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Network administrative access to the AWS account

## Architecture
The VPC has a CIDR block of 10.0.0.0/16. It includes an Internet Gateway for external access and three public subnets (10.0.1.0/24, 10.0.2.0/24, 10.0.3.0/24), three private subnets (10.0.11.0/24, 10.0.12.0/24, 10.0.13.0/24), and three database subnets (10.0.21.0/24, 10.0.22.0/24, 10.0.23.0/24), each spanning across three Availability Zones.

## Operations

### Scaling
VPC CIDR blocks cannot be scaled directly. To accommodate growth, consider VPC peering or creating a new VPC with a larger CIDR range and migrating resources.

### Monitoring
Key metrics: VPC Flow Logs for traffic analysis, AWS Network Firewall metrics if implemented. Monitor CloudWatch logs for any network-related errors or anomalies.

### Backup & Recovery
VPC configurations are not typically backed up in the traditional sense. Changes are managed via Infrastructure as Code. Recovery involves reapplying the IaC configurations.

### Common Issues
### Subnet IP Exhaustion
- **Diagnosis**: Check subnet utilization. If a subnet is close to full, consider expanding its CIDR block or migrating resources to a less utilized subnet.
- **Resolution**: If expanding is not feasible, create new subnets with additional CIDR blocks and update routing tables and resource configurations.

## Rollback Procedure
1. Revert the Infrastructure as Code (IaC) changes.
2. Apply the reverted IaC using the deployment tool (e.g., `terraform apply`).
3. Verify network connectivity and resource accessibility.
