# Runbook: App VPC

## Overview
The App VPC provides a logically isolated network within AWS for hosting application resources. It defines the IP address range and network configurations for all resources deployed within it.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM user or role with network management privileges

## Architecture
The VPC spans across multiple Availability Zones to ensure high availability. It includes public subnets for internet-facing resources and private subnets for application and data tiers.

## Operations

### Scaling
VPC scaling is primarily managed by its CIDR block and subnet configurations. To scale the IP address space, a new VPC with a larger CIDR block would need to be provisioned and resources migrated. Subnet scaling involves adding new subnets within the existing VPC.

### Monitoring
Key metrics include VPC Flow Logs for traffic analysis and network ACL hit counts. Monitor for any changes in network traffic patterns that may indicate an issue.

### Backup & Recovery
VPC configurations are managed via Infrastructure as Code (IaC). Recovery involves re-applying the IaC configurations. No specific backup procedure for the VPC itself is required beyond version control of the IaC.

### Common Issues
### Subnet IP exhaustion
Diagnosis: Monitor subnet usage. If a subnet is nearing its IP address limit, plan for expansion.
Resolution: Add new subnets or expand existing ones if possible, or consider a new VPC with a larger CIDR.

### Routing issues
Diagnosis: Use VPC Network Reachability Analyzer and check route tables.
Resolution: Ensure route tables are correctly configured to direct traffic to the appropriate targets (e.g., NAT gateways, Internet Gateway).

## Rollback Procedure
1. Revert the IaC commit that modified the VPC configuration.
2. Apply the reverted IaC configuration.
3. Verify network connectivity and resource accessibility.
