# Runbook: App VPC

## Overview
The App VPC provides a logically isolated network within AWS for the microservices platform. It defines the IP address space and network boundaries.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Network access to the AWS environment

## Architecture
The VPC spans multiple Availability Zones and contains public and private subnets to segment resources. It includes an Internet Gateway for public access and NAT Gateways for outbound internet connectivity from private subnets.

## Operations

### Scaling
VPC CIDR blocks are generally static. Scaling involves adding new subnets or modifying routing as needed, which is outside the scope of a typical runbook for a static VPC configuration.

### Monitoring
Key metrics: VPC Flow Logs (to monitor network traffic patterns), Network ACLs (to monitor traffic filtering). Alarms can be configured for unusual traffic spikes or denied connections.

### Backup & Recovery
VPC configuration is managed via Infrastructure as Code. Recovery involves re-deploying the VPC definition from the IaC repository.

### Common Issues
### Connectivity issues to/from the VPC
**Diagnosis**: Check VPC Flow Logs for denied traffic, review Network ACLs and Security Group rules. Ensure NAT Gateway is functioning and has EIP.
**Resolution**: Adjust NACLs, Security Groups, or application configurations as needed. Verify NAT Gateway health and route tables.

## Rollback Procedure
1. Revert the IaC commit that modified the VPC configuration.
2. Apply the changes using the IaC tool (e.g., `terraform apply`).
3. Verify network connectivity and resource accessibility.
