# Runbook: App VPC

## Overview
The App VPC provides a private network space for the application's resources, isolating them from the public internet and other AWS environments. It defines the IP address range and network boundaries for all deployed resources.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Network administrative access

## Architecture
The VPC uses a 10.0.0.0/16 CIDR block, encompassing multiple public and private subnets across two Availability Zones (a and b). Internet Gateway is attached for internet access from public subnets. NAT Gateways are deployed in each Availability Zone for outbound internet access from private subnets.

## Operations

### Scaling
1. To scale the VPC's IP address space, a new CIDR block can be associated with the VPC.
2. For network traffic scaling, consider adjusting NAT Gateway and VPN/Direct Connect capacities if applicable.
3. Subnet scaling involves creating new subnets within the VPC CIDR, ensuring proper routing.

### Monitoring
Key metrics: VPC Flow Logs (enabled for network traffic analysis). Monitor for any unusual traffic patterns or denied flows.  Review CloudWatch logs for the KMS key used for encrypting flow logs.

### Backup & Recovery
VPC configurations are generally static and managed by Infrastructure as Code. In case of accidental deletion, the VPC can be recreated using the Terraform configuration. Resource data within the VPC (e.g., RDS, ElastiCache) should have separate backup and recovery plans.

### Common Issues
### Connectivity Issues
- **Diagnosis**: Network ACLs, Security Groups, Route Tables not configured correctly. Ensure routes to NAT Gateways and Internet Gateway are present.
- **Resolution**: Review and correct NACLs, Security Groups, and Route Table entries. Use VPC Reachability Analyzer for diagnosis.

## Rollback Procedure
1. Revert the Infrastructure as Code changes related to the VPC.
2. Apply the reverted configuration using Terraform.
3. Verify network connectivity and resource accessibility.
