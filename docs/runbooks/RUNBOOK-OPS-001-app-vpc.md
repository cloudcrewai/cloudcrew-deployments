# Runbook: App VPC

## Overview
The App VPC provides a private, isolated network environment for the application resources. It defines the IP address space and network boundaries for all deployed components.

## Prerequisites
- AWS CLI configured with appropriate permissions
- VPC read access in the AWS account

## Architecture
The VPC has a CIDR block of 10.0.0.0/16. It is configured with 2 Availability Zones, utilizing public subnets for internet-facing resources and private subnets for application and database tiers. NAT Gateways are provisioned in each Availability Zone for outbound internet access from private subnets.

## Operations

### Scaling
VPC scaling is generally not required as the CIDR block is provisioned upfront. If IP address exhaustion becomes a concern, a new VPC with a larger CIDR or VPC peering may be necessary.

### Monitoring
Key metrics to monitor include VPC flow logs for network traffic analysis and subnet IP address utilization. Alerts can be configured for critical threshold breaches.

### Backup & Recovery
VPC configurations are managed via Infrastructure as Code. In case of a VPC-level issue, the VPC can be recreated by applying the IaC, ensuring consistent configuration.

### Common Issues
### Subnet IP Address Exhaustion
Diagnosis: Monitor available IP addresses within subnets. If a subnet is nearing exhaustion, it may impact new resource deployments or scaling.
Resolution: Evaluate if resources can be moved to subnets with more available IPs, or consider expanding the VPC CIDR or implementing VPC peering if persistent growth is expected.

## Rollback Procedure
1. Revert the IaC commit that modified the VPC configuration.
2. Apply the reverted IaC using `terraform apply`.
3. Verify network connectivity and resource accessibility.
