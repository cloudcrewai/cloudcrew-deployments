# Runbook: ECS Fargate

## Overview
ECS Fargate is a serverless compute engine for containers that makes it easy to build and run applications without managing servers. It abstracts away the underlying infrastructure for the application's containerized workloads.

## Prerequisites
- AWS CLI configured with appropriate permissions
- ECS Cluster created
- Task Definition registered
- IAM roles for ECS tasks and service

## Architecture
ECS Fargate tasks are launched within the private subnets of the VPC. They are typically fronted by an Application Load Balancer for ingress traffic and may interact with other AWS services like RDS and ElastiCache. Security Groups control inbound and outbound access.

## Operations

### Scaling
1. Navigate to the ECS console.
2. Select the cluster and service.
3. Under the 'Service' tab, click 'Update'.
4. Adjust the 'Desired tasks' count for manual scaling.
5. Configure Auto Scaling settings (minimum, maximum, desired tasks, scaling policies) based on metrics like CPUUtilization or MemoryUtilization.

### Monitoring
Key CloudWatch metrics to monitor for ECS Fargate services include: CPUUtilization, MemoryUtilization, RunningTaskCount, HealthyHostCount. Recommended alarm thresholds: CPUUtilization > 80%, MemoryUtilization > 85%. Monitor ECS service events for deployment failures or task issues.

### Backup & Recovery
ECS Fargate services are generally stateless. Data persistence should be managed by external services (e.g., RDS, S3). To recover a service, re-deploy the task definition and service configuration via IaC. If persistent data is lost, restore it from the respective data store's backup.

### Common Issues
Consult CloudWatch logs for errors.

## Rollback Procedure
1. Revert the IaC commit that introduced the change to the ECS service or task definition.
2. Apply the reverted IaC using `terraform apply`.
3. Monitor the ECS service for successful deployment and verify application functionality.
