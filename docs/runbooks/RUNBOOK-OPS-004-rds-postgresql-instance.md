# Runbook: RDS PostgreSQL Instance

## Overview
The RDS PostgreSQL instance serves as the primary relational database for the application, storing structured data and ensuring data integrity across multiple Availability Zones for high availability.

## Prerequisites
- AWS CLI configured with appropriate permissions
- RDS instance creation permissions
- VPC with appropriate subnets and security groups configured

## Architecture
The RDS PostgreSQL instance is deployed in a Multi-AZ configuration across private subnets in Availability Zones 'a' and 'b'. A security group allows inbound connections from the ECS service's security group on the PostgreSQL port (5432).

## Operations

### Scaling
1. Navigate to the RDS console.
2. Select the database instance.
3. Click 'Modify'.
4. Under 'Instance configuration', change the 'DB instance class' to a larger or smaller size as needed.
5. For storage scaling, adjust the 'Allocated storage' size. Consider enabling 'Enable storage autoscaling'.
6. Apply the changes. Note that some instance modifications may require a brief downtime.

### Monitoring
Key CloudWatch metrics: CPUUtilization, FreeStorageSpace, DatabaseConnections, ReadIOPS, WriteIOPS, ReadLatency, WriteLatency. Recommended alarm thresholds: FreeStorageSpace < 20% of allocated storage, CPUUtilization > 80% sustained, Read/Write Latency > 50ms.

### Backup & Recovery
Automated backups are enabled with a retention period of X days (default 7, configurable). Point-in-time recovery (PITR) is available. To restore: 1. Navigate to the RDS console. 2. Select the instance. 3. Click 'Actions' -> 'Restore to point in time'. 4. Specify the desired timestamp and a new instance identifier. The restore process creates a new RDS instance. RTO is typically within minutes for automated backups.

### Common Issues
Consult CloudWatch logs for errors.

## Rollback Procedure
1. Revert the IaC commit that modified the RDS instance configuration.
2. Apply the reverted IaC using `terraform apply`.
3. If a restore was performed, ensure the application is pointing to the correct database endpoint.
4. Verify database accessibility and data integrity.
