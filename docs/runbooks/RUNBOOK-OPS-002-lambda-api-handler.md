# Runbook: Lambda API Handler

## Overview
The Lambda API Handler is a serverless compute service responsible for executing the business logic of the API. It processes requests received from API Gateway, interacts with other AWS services like DynamoDB, and returns responses.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM permissions to execute Lambda functions and access other required services (e.g., DynamoDB, Secrets Manager)
- Access to CloudWatch Logs for debugging

## Architecture
This Lambda function is triggered by API Gateway. It is configured with Python 3.12 runtime and has a specified handler ('app.handler'). It operates within the production environment and is designed to be scalable on demand.

## Operations

### Scaling
Lambda scales automatically based on the number of incoming requests. Manual scaling is not applicable as it's a serverless, event-driven service. 

To adjust provisioned concurrency (if needed for latency-sensitive workloads): 
1. Navigate to the Lambda console.
2. Select the 'Lambda API Handler' function.
3. Go to the 'Configuration' tab and then 'Concurrency'.
4. Configure 'Provisioned concurrency'.

### Monitoring
Key CloudWatch metrics for Lambda:
- `Invocations` (Number of times the function is executed)
- `Errors` (Number of invocations that resulted in an error)
- `Duration` (Execution time)
- `Throttles` (Number of invocations throttled due to concurrency limits)

Recommended alarm thresholds:
- `Errors` > 0 for 5 minutes
- `Duration` > 1000ms for 5 minutes
- `Throttles` > 0 for 5 minutes

### Backup & Recovery
Lambda functions are code and configuration. Recovery from an issue is achieved by redeploying the correct version of the function code and its configuration via the IaC pipeline.

### Common Issues
### Lambda function timeout
**Diagnosis**: The function execution exceeds the configured timeout limit. Check CloudWatch logs for execution details and duration.
**Resolution**: Optimize the function's code for performance. If optimization is not sufficient, increase the function's timeout setting in its configuration, ensuring it does not exceed the service limit.

## Rollback Procedure
1. Revert the IaC commit that introduced the faulty Lambda function code or configuration.
2. Apply the reverted IaC (e.g., `terraform apply`).
3. Verify the function's successful execution and expected behavior.
