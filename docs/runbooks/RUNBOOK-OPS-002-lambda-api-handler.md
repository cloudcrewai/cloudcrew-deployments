# Runbook: Lambda API Handler

## Overview
The Lambda API Handler is a serverless compute function responsible for executing the business logic of the API. It processes requests received from API Gateway, interacts with data stores like DynamoDB, and returns responses.

## Prerequisites
- AWS CLI configured with appropriate permissions.
- IAM permissions to execute Lambda functions and access other AWS services (e.g., DynamoDB, Secrets Manager).
- `python3.12` runtime available.
- Code deployed to the Lambda function.

## Architecture
A Python 3.12 Lambda function triggered by API Gateway. It uses the `app.handler` function as its entry point. It is configured with 512MB of memory and is expected to handle approximately 5,000,000 invocations per month with an average duration of 150ms.

## Operations

### Scaling
Lambda functions scale automatically based on the number of incoming requests. AWS manages the underlying infrastructure to meet demand. The concurrency limit for Lambda can be adjusted in the AWS console if necessary, but for this configuration, automatic scaling is sufficient.

### Monitoring
Key CloudWatch metrics to monitor:
- `Invocations`: Number of times the Lambda function has been invoked.
- `Errors`: Number of invocations that resulted in an error.
- `Duration`: The execution time of the Lambda function.
- `Throttles`: Number of times invocations were throttled due to concurrency limits.

Recommended alarm thresholds:
- `Errors` > 0 for 1 minute (indicates a functional issue).
- `Duration` > 500ms for 5 minutes (indicates potential performance degradation).
- `Throttles` > 0 for 1 minute (indicates concurrency issues).

### Backup & Recovery
Lambda functions are stateless and their code is managed via Infrastructure as Code. To recover from deletion or corruption, redeploy the function using the IaC. Any state is managed in persistent services like DynamoDB.

### Common Issues
### 1. Function timeouts:
- **Diagnosis**: Lambda function exceeds the configured timeout limit before completing execution.
- **Resolution**: Increase the timeout setting for the Lambda function in the AWS console or IaC. Analyze logs to identify performance bottlenecks and optimize the code.

### 2. `Task timed out after X seconds` in CloudWatch logs:
- **Diagnosis**: Similar to function timeouts, but specifically indicates the Lambda execution environment timed out.
- **Resolution**: Optimize the function's code for performance. Ensure necessary dependencies are included and efficiently loaded. Increase the timeout if the task legitimately requires more time, but investigate the root cause first.

### 3. `Lambda was not able to be called because of a permissions error`:
- **Diagnosis**: The Lambda function's execution role lacks the necessary IAM permissions to access other AWS services (e.g., DynamoDB, Secrets Manager).
- **Resolution**: Review the Lambda function's execution role in IAM and add the required permissions. Ensure the role is correctly associated with the Lambda function.

## Rollback Procedure
1. Revert the Infrastructure as Code commit that modified the Lambda function's code or configuration.
2. Apply the changes using the IaC tool (e.g., `terraform apply`).
3. Verify that the Lambda function executes correctly and responds to API requests.
