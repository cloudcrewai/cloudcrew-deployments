# Runbook: Lambda API Handler

## Overview
The Lambda API Handler is a serverless compute service responsible for executing the business logic of the API. It processes requests received from API Gateway, interacts with data stores like DynamoDB, and returns responses.

## Prerequisites
- AWS CLI configured with appropriate permissions.
- IAM permissions to execute Lambda functions and access other AWS services (DynamoDB, KMS, Secrets Manager, etc.).
- Access to CloudWatch Logs for debugging.

## Architecture
Deployed as a Lambda function, triggered by API Gateway. It operates within a VPC if specific network resources are required, otherwise it runs in the default Lambda environment. It uses AWS SDKs to interact with other services.

## Operations

### Scaling
1. Lambda automatically scales based on the number of incoming requests.
2. To adjust concurrency limits: Navigate to the Lambda console, select the function, go to 'Concurrency' settings, and adjust the 'Reserved Concurrency' or 'Provisioned Concurrency' if needed.
3. To adjust memory and timeout: Navigate to the Lambda console, select the function, and modify the 'General configuration' settings.

### Monitoring
Key CloudWatch metrics: 
- `Invocations` (number of times the function was called)
- `Errors` (number of invocations that resulted in an error)
- `Duration` (execution time)
- `Throttles` (requests throttled due to concurrency limits). 
Recommended alarm thresholds: `Errors` > 0 in 5 minutes, `Throttles` > 0 in 5 minutes, `Duration` > 500ms P90 for 5 minutes.

### Backup & Recovery
Lambda functions are code deployments. Restore by re-deploying the function from its source code repository via the IaC. Versioning can be enabled on the Lambda function for easier rollbacks to previous code versions.

### Common Issues
### Lambda function timeouts
*   **Diagnosis**: Check CloudWatch Logs for execution time exceeding the configured timeout. Identify long-running operations within the function.
*   **Resolution**: Optimize the function code for performance, increase the timeout setting in Lambda configuration, or refactor to use asynchronous patterns (e.g., Step Functions, SQS).

### Lambda function permissions errors
*   **Diagnosis**: Review CloudWatch Logs for `AccessDeniedException` or similar errors. Verify the IAM role attached to the Lambda function has the necessary permissions for all services it interacts with.
*   **Resolution**: Update the Lambda function's execution IAM role with the required permissions. Ensure policies are least-privilege.

## Rollback Procedure
1. Revert the IaC commit that modified the Lambda function configuration or code.
2. Apply the reverted IaC using `terraform apply` or equivalent.
3. If necessary, manually trigger a deployment of a previous Lambda function version via the AWS console or AWS CLI.
