# Runbook: Route53 DNS

## Overview
Route53 is a highly available and scalable cloud Domain Name System (DNS) web service. It translates human-readable domain names into the numeric IP addresses needed for locating and connecting to services.

## Prerequisites
- AWS CLI configured with appropriate permissions.
- IAM user/role with Route53 read access.

## Architecture
Acts as the public-facing DNS for the 'three-tier-web-app' project, resolving the application's domain to its entry point, likely an Application Load Balancer.

## Operations

### Scaling
Route53 is a managed AWS service and scales automatically. No manual scaling configuration is required.

### Monitoring
Key metrics are not directly applicable as Route53 is a managed service. Monitor DNS query logs if enabled. For application availability, monitor the health of the services Route53 points to (e.g., ALB health checks).

### Backup & Recovery
Route53 hosted zones are automatically replicated across multiple AWS Availability Zones. No backup or recovery procedures are needed for the DNS service itself. Restore operations involve re-associating DNS records if they are inadvertently deleted.

### Common Issues
### DNS resolution failures
- **Diagnosis**: Verify DNS records in Route53 are correctly configured and pointing to the correct resources (e.g., ALB, CloudFront distribution).
- **Resolution**: Check for typos, ensure record types (A, CNAME) are appropriate, and confirm the target resource is healthy.

### Propagation delays
- **Diagnosis**: Changes to DNS records can take time to propagate globally.
- **Resolution**: Allow up to 48 hours for full propagation, though it is often much faster. Use tools like `dig` or `nslookup` from different locations to check propagation status.

## Rollback Procedure
1. Revert DNS record changes in the Route53 console or via IaC.
2. Wait for DNS propagation to complete.
