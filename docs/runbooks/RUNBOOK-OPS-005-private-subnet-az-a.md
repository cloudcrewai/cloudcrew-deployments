# Runbook: Private Subnet AZ-A

## Overview
This is a private subnet within Availability Zone A of the 'App VPC'. Resources within this subnet do not have direct internet access. Outbound internet connectivity is typically achieved via a NAT Gateway.

## Prerequisites
- AWS CLI configured with appropriate permissions to manage VPC resources.
- Understanding of subnet CIDR ranges and routing.

## Architecture
Part of the 'App VPC' (10.0.0.0/16). Uses CIDR block 10.0.11.0/24. Associated with a private Route Table that directs internet-bound traffic (0.0.0.0/0) to the NAT Gateway in AZ-A. Hosts application instances (e.g., ECS tasks, EC2 instances) that should not be directly accessible from the internet.

## Operations

### Scaling
Subnet scaling is not a direct concept. To accommodate more resources, consider:
1. Extending the CIDR range if the VPC has available space.
2. Creating additional private subnets in the same or different AZs.

### Monitoring
While subnets themselves don't have direct CloudWatch metrics, monitor resources within the subnet, such as:
- Compute instances (CPU, Memory utilization)
- Database instance metrics (if applicable)
- Network ACL logs for traffic patterns and potential denies.
Recommended Alarm Thresholds: Monitor for any denied traffic in Network ACLs associated with this subnet.

### Backup & Recovery
Subnets are configuration elements of a VPC. Backups are not applicable. In case of deletion, a new subnet would need to be recreated with the same CIDR and associated route tables.

### Common Issues
### IP Address Exhaustion
*   **Diagnosis**: New resources cannot be launched within the subnet due to lack of available IP addresses.
*   **Resolution**: Review current IP usage within the subnet's CIDR. If necessary, expand the subnet's CIDR range (if VPC has capacity) or create a new subnet. 

### Connectivity Issues to NAT Gateway
*   **Diagnosis**: Resources in the private subnet cannot reach the internet, indicating a problem with the route to the NAT Gateway.
*   **Resolution**: Verify the Route Table associated with this subnet. Ensure `0.0.0.0/0` traffic is correctly routed to the NAT Gateway's Elastic Network Interface (ENI) in AZ-A. Check NAT Gateway status and CloudWatch metrics.

## Rollback Procedure
1. Revert any IaC changes related to the subnet's CIDR or Route Table associations.
2. Apply the reverted IaC.
3. Verify connectivity and resource status.
