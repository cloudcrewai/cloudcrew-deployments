# Runbook: Private Subnet AZ-B

## Overview
Private Subnet AZ-B is a network segment within Availability Zone B designed to host resources that should not be directly accessible from the internet. It relies on NAT Gateways for outbound internet access.

## Prerequisites
- AWS CLI with permissions to view and manage subnets and route tables.
- An existing VPC with NAT Gateways configured in the same AZ.

## Architecture
Located in Availability Zone B, this subnet uses the CIDR block 10.0.12.0/24. It is intended for backend services, databases, and application servers that require isolation. Its route table is configured to direct internet-bound traffic to the NAT Gateway in AZ-B.

## Operations

### Scaling
1. New private subnets can be created in AZ-B or other Availability Zones to further segment resources or to accommodate growth.
2. The CIDR block of the private subnet can be adjusted, but this requires careful consideration of the overall VPC IP address management strategy.

### Monitoring
Monitor IP address utilization within the subnet. Enable VPC Flow Logs to analyze traffic patterns and identify potential security issues or performance bottlenecks. No specific CloudWatch alarms are directly configured for the subnet itself.

### Backup & Recovery
Private subnets are network configurations and are not directly backed up. Their definition is managed via Infrastructure as Code. If a private subnet is deleted, it can be recreated using the IaC.

### Common Issues
### No Internet Access for Private Resources
Diagnosis: Resources within the private subnet cannot reach external services.
Resolution: Ensure the route table associated with the private subnet has a default route (0.0.0.0/0) pointing to the NAT Gateway in the same AZ. Verify the NAT Gateway is operational and has internet connectivity. Check security group and Network ACL rules that might be blocking outbound traffic.

## Rollback Procedure
1. Revert the Infrastructure as Code (IaC) changes related to the private subnet.
2. Apply the reverted IaC configuration.
3. Verify that resources within the private subnet retain their required network access.
