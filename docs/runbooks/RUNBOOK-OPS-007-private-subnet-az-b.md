# Runbook: Private Subnet AZ-B

## Overview
The Private Subnet in Availability Zone B is designed to host resources that do not require direct internet access, enhancing security. It is part of the IoT VPC.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Network administration knowledge

## Architecture
Located in Availability Zone B with a defined CIDR block. Resources in this subnet use the NAT Gateway in AZ-B for outbound internet access. It is peered with other subnets and connected via VPC endpoints for secure AWS service access.

## Operations

### Scaling
Subnet scaling is managed by CIDR block allocation. To expand the IP address range within this AZ, a new CIDR block can be associated with the VPC and then carved out for this subnet.

### Monitoring
Key metrics: Subnet IP address utilization. Monitor traffic routed through the NAT Gateway. Monitor the health and availability of resources deployed within this subnet (e.g., Lambda functions, Kinesis).

### Backup & Recovery
Subnet configurations are managed via Infrastructure as Code (IaC). Recovery involves re-deploying the subnet configuration from the IaC repository.

### Common Issues
### Inability to reach external resources
**Diagnosis**: Verify that the route table associated with this private subnet correctly directs internet-bound traffic (0.0.0.0/0) to the NAT Gateway in AZ-B. Check NAT Gateway's CloudWatch metrics for errors.
**Resolution**: Correct the route table configuration. Ensure the NAT Gateway is healthy and has available ports.

## Rollback Procedure
1. Revert the IaC commit that modified the private subnet configuration.
2. Execute 'terraform apply' to redeploy the previous state.
3. Verify network connectivity for resources within the subnet.
