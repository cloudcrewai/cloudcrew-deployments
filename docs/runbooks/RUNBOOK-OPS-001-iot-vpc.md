# Runbook: IoT VPC

## Overview
The IoT VPC provides a private network space for the IoT data pipeline components in the us-east-1 region. It utilizes a CIDR block of 10.0.0.0/16 and is configured across 2 Availability Zones for high availability.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Network administration knowledge

## Architecture
Consists of a main CIDR block (10.0.0.0/16) with associated public and private subnets across two Availability Zones (a and b). Includes an Internet Gateway, NAT Gateways in each AZ for outbound internet access from private subnets, and VPC endpoints for private communication with AWS services.

## Operations

### Scaling
VPC scaling is primarily related to subnet CIDR management. To add more IP address space, a new CIDR block can be associated with the VPC. Subnet scaling involves creating new subnets within the VPC's CIDR range in desired Availability Zones.

### Monitoring
Key metrics: VPC Flow Logs for traffic analysis, VPC Endpoint metrics for connection health. Monitor for IP address exhaustion in subnets. Review NACL and Security Group rules for any anomalies.

### Backup & Recovery
VPC configurations are managed via Infrastructure as Code (IaC). Recovery involves re-deploying the VPC configuration from the IaC repository.

### Common Issues
### Subnet IP address exhaustion
**Diagnosis**: Monitor CloudWatch metrics for subnet utilization. Check Route 53 for DNS resolution issues if using private hosted zones.
**Resolution**: Associate a new, larger CIDR block to the VPC or re-architect subnets to optimize IP usage.

## Rollback Procedure
1. Revert the IaC commit that modified the VPC configuration.
2. Execute 'terraform apply' to redeploy the previous state.
3. Verify network connectivity and resource accessibility.
