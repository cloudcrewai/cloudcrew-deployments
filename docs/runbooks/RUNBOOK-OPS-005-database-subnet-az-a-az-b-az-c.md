# Runbook: Database Subnet AZ-A, AZ-B, AZ-C

## Overview
These database subnets are specifically designated for housing RDS database instances. They are typically configured within a private subnet to restrict direct internet access, enhancing database security.

## Prerequisites
- AWS CLI configured with appropriate permissions
- VPC with appropriate routing and security group configurations
- RDS Subnet Group created and associated with the RDS instance

## Architecture
These subnets (10.0.21.0/24, 10.0.22.0/24, 10.0.23.0/24) reside in separate Availability Zones (a, b, c respectively) within the 'App VPC'. They are configured to be part of a private RDS subnet group, ensuring RDS instances are not publicly accessible.

## Operations

### Scaling
The IP address range of these subnets is fixed. To accommodate more instances or larger databases requiring more IP addresses, new subnets with additional CIDR blocks can be created and added to the RDS Subnet Group. RDS instance scaling (instance size, storage) is handled independently.

### Monitoring
Monitor CloudWatch metrics for RDS instances residing in these subnets (e.g., CPU Utilization, Memory Usage, Disk Queue Depth, Network Traffic). Analyze VPC Flow Logs for traffic patterns. Monitor Network ACLs for DENY activity.

### Backup & Recovery
Database subnet configurations are managed as part of the VPC definition via Infrastructure as Code. Recovery involves reapplying the IaC configurations. RDS backups and restore procedures are configured separately within the RDS service.

### Common Issues
### RDS instance not accessible from application instances
- **Diagnosis**: Verify the RDS instance is within the correct subnet group. Ensure the Security Group attached to the RDS instance allows inbound traffic on the database port (e.g., 5432 for PostgreSQL) from the application's Security Group or private IP range. Check route tables for the database subnets to ensure they can reach the application subnets if necessary.
- **Resolution**: Correct the RDS Subnet Group and Security Group configurations. Adjust route tables if inter-subnet communication is required.

## Rollback Procedure
1. Revert the Infrastructure as Code (IaC) changes related to the database subnets.
2. Apply the reverted IaC using the deployment tool (e.g., `terraform apply`).
3. Verify RDS instances can be accessed as expected by authorized resources.
