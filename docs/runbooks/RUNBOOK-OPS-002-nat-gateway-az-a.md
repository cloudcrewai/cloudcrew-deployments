# Runbook: NAT Gateway AZ-A

## Overview
The NAT Gateway in Availability Zone A enables instances in private subnets within AZ-A to connect to the internet or other AWS services, but prevents the internet from initiating connections with those instances.

## Prerequisites
- AWS CLI configured with permissions to manage NAT Gateways and Elastic IPs.
- A public subnet in the same Availability Zone (AZ-A) to host the NAT Gateway.
- An Elastic IP address associated with the NAT Gateway.

## Architecture
The NAT Gateway resides in the public subnet 'Public Subnet AZ-A' and is associated with an Elastic IP. Route tables for private subnets in AZ-A are configured to direct outbound internet traffic through this NAT Gateway.

## Operations

### Scaling
1. To scale NAT Gateway capacity, allocate additional Elastic IP addresses and create new NAT Gateways in the same or different public subnets.
2. Update the route tables of the relevant private subnets to direct traffic to the new NAT Gateways.
3. Distribute traffic across multiple NAT Gateways for increased throughput and availability.

### Monitoring
Key CloudWatch metrics for NAT Gateway include `BytesInFromSource`, `BytesOutToDestination`, `ActiveConnectionCount`, and `PacketsDropCount`. Monitor `PacketsDropCount` for signs of network congestion or capacity issues. Consider alarms for sustained high connection counts or packet drops.

### Backup & Recovery
NAT Gateways are managed AWS services and do not require traditional backups. High availability is achieved by deploying NAT Gateways in multiple Availability Zones. If a NAT Gateway fails, traffic is automatically rerouted if an alternative NAT Gateway is configured in another AZ.

### Common Issues
### Internet Connectivity Failure from Private Subnets
Diagnosis: Instances in private subnets cannot reach external resources.
Resolution: Verify that the NAT Gateway is in a 'Ready' state. Check route tables for the private subnets to ensure they point to the correct NAT Gateway. Confirm the NAT Gateway has an associated Elastic IP and is deployed in a public subnet. Examine VPC Flow Logs for denied traffic.

## Rollback Procedure
1. Revert the Infrastructure as Code (IaC) changes related to the NAT Gateway configuration.
2. Apply the reverted IaC configuration.
3. Verify that private instances can still access the internet if the rollback involves replacing a NAT Gateway.
