# Runbook: Private Subnet AZ-A

## Overview
The private subnet in Availability Zone A is a segment of the VPC's IP address space intended for resources that should not be directly accessible from the internet, such as application servers and databases.

## Prerequisites
- AWS CLI configured with appropriate permissions
- VPC must exist
- Route table associated with this subnet must have a route to the NAT Gateway for outbound internet access

## Architecture
Located in AZ-A. Hosts application components like ECS tasks. It relies on the NAT Gateway in AZ-A for outbound internet connectivity.

## Operations

### Scaling
Subnets are network constructs. Scaling involves deploying more resources (e.g., ECS tasks) within the subnet or adding more private subnets in other AZs.

### Monitoring
Key metrics: VPC Flow Logs to monitor traffic. Monitor resources (e.g., ECS tasks) deployed within the subnet. Check NAT Gateway metrics for outbound connectivity health.

### Backup & Recovery
Subnets are part of the VPC configuration. Recovery involves re-deploying the VPC and its subnet definitions from IaC.

### Common Issues
### Instances in private subnet AZ-A cannot access external resources
**Diagnosis**: Verify route table for this subnet has a route to the NAT Gateway for `0.0.0.0/0`. Check Security Groups and Network ACLs applied to resources. Ensure NAT Gateway is functioning and has internet access.
**Resolution**: Correct route table, Security Groups, NACLs, or NAT Gateway configuration.

## Rollback Procedure
1. Revert the IaC commit that modified the private subnet configuration.
2. Apply the changes using the IaC tool.
3. Verify resource connectivity.
