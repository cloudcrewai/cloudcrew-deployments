# Runbook: ML Platform VPC

## Overview
The ML Platform VPC (Virtual Private Cloud) provides a logically isolated network environment for the SageMaker ML platform resources. It spans two Availability Zones for high availability and includes public subnets for NAT Gateways and private subnets for SageMaker resources, ensuring controlled access and security.

## Prerequisites
- AWS CLI configured with appropriate permissions for VPC operations.
- Network administrator access or IAM role with VPC modification privileges.

## Architecture
The VPC uses a CIDR block of 10.0.0.0/16. It is provisioned across two Availability Zones ('a' and 'b'). Public subnets (10.0.1.0/24 and 10.0.2.0/24) host NAT Gateways, enabling outbound internet access for resources in private subnets. Private subnets (10.0.11.0/24 and 10.0.12.0/24) are designated for SageMaker resources, isolating them from direct internet access.

## Operations

### Scaling
1. **Subnet Expansion**: To accommodate more resources, new subnets can be added within existing or new Availability Zones. This involves creating new `aws_subnet` resources in Terraform with appropriate CIDR blocks.
2. **VPC CIDR Adjustment**: If the 10.0.0.0/16 CIDR becomes insufficient, a new, larger CIDR block can be allocated, requiring careful planning to avoid IP conflicts.

### Monitoring
Key metrics to monitor include:
- **VPC Flow Logs**: Analyze network traffic patterns for unusual activity or high volumes.
- **Subnet IP Address Utilization**: Ensure subnets are not nearing capacity. CloudWatch metrics can be configured for this.
- **NAT Gateway Metrics**: Monitor `ActiveConnectionCount` and `PacketsDropCount` for potential bottlenecks or failures.

### Backup & Recovery
VPC configurations are not directly backed up in the traditional sense. Recovery involves re-deploying the VPC definition from the Infrastructure-as-Code (IaC) repository. Ensure the IaC is version-controlled and backed up.

### Common Issues
### Inability to access AWS services from private subnets
- **Diagnosis**: Check NAT Gateway status and route tables. Ensure the route table associated with private subnets directs 0.0.0.0/0 traffic to the NAT Gateway.
- **Resolution**: Verify NAT Gateway is running and has an Elastic IP. Confirm route table configurations in the VPC console.

### IP address exhaustion in subnets
- **Diagnosis**: Monitor subnet IP usage. If a subnet is full, new resources cannot be launched within it.
- **Resolution**: Add new subnets with available CIDR blocks or expand existing subnet CIDRs if feasible and safe, then update IaC accordingly.

## Rollback Procedure
1. Revert the IaC commit that introduced the changes to the VPC configuration.
2. Execute `terraform apply` to revert the infrastructure to the previous state.
3. Verify network connectivity and resource accessibility post-rollback.
