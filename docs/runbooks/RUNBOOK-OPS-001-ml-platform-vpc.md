# Runbook: ML Platform VPC

## Overview
The ML Platform VPC serves as the isolated network boundary for all SageMaker ML Platform resources. It utilizes a CIDR block of 10.0.0.0/16 and is configured with public and private subnets across two Availability Zones for high availability.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM permissions to manage VPC resources

## Architecture
Consists of two public subnets (10.0.1.0/24, 10.0.2.0/24) and two private subnets (10.0.11.0/24, 10.0.12.0/24) across Availability Zones A and B. Internet Gateway is attached for internet access. NAT Gateways in each AZ provide outbound internet connectivity for resources in private subnets.

## Operations

### Scaling
VPC scaling is primarily related to CIDR block management and subnet allocation. 
1. To add more IP address space, a new CIDR block can be associated with the VPC.
2. New subnets can be created within existing or new CIDR blocks to accommodate additional resources.
3. For high availability, ensure subnets are distributed across multiple Availability Zones.

### Monitoring
Key metrics: 
- VPC Flow Logs: Monitor traffic patterns and identify anomalies. Enable VPC Flow Logs and send logs to CloudWatch Logs or S3.
- Network ACLs: Monitor deny rules to identify potential security issues or misconfigurations.
- Route Tables: Monitor changes to ensure correct traffic routing.

### Backup & Recovery
VPCs themselves are not directly backed up. Recovery involves re-creating the VPC configuration via IaC. In case of accidental deletion, the IaC should be used to provision a new VPC with the same configuration.

### Common Issues
### Subnet route issues
**Diagnosis**: Resources in a subnet cannot reach their destination (e.g., internet, other AWS services).
**Resolution**: Verify the subnet's route table is correctly associated and contains the appropriate routes (e.g., to NAT Gateway for outbound internet, VPC endpoints for AWS services). Ensure NACLs and Security Groups allow traffic.

### IP address exhaustion
**Diagnosis**: New resources cannot be launched due to lack of available IP addresses in a subnet.
**Resolution**: Review subnet CIDR ranges. If necessary, associate a new, larger CIDR block with the VPC and create new subnets, or expand existing subnet CIDR ranges if feasible.

## Rollback Procedure
1. Revert the IaC commit that modified the VPC configuration.
2. Execute `terraform apply` to revert the changes.
3. Verify network connectivity and resource accessibility.
