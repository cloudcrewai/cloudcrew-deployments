# Runbook: NAT Gateway AZ-B

## Overview
The NAT Gateway in Availability Zone B allows resources in private subnets within AZ-B to initiate outbound connections to the internet while preventing unsolicited inbound connections from the internet.

## Prerequisites
- AWS CLI configured with appropriate permissions.
- IAM permissions to describe VPCs, NAT Gateways, Elastic IPs, and route tables.
- A public subnet in AZ-B and an Elastic IP address associated with this NAT Gateway.

## Architecture
Resides in the public subnet of AZ-B. Its route table is configured to direct internet-bound traffic (0.0.0.0/0) from private subnets in AZ-B to this NAT Gateway. It uses an Elastic IP for a static public address.

## Operations

### Scaling
NAT Gateways are managed services and automatically scale to handle network traffic. For extremely high throughput requirements, consider multiple NAT Gateways or alternative solutions.

### Monitoring
Key metrics include `BytesInFromSource`, `BytesOutToSource`, `PacketsInFromSource`, `PacketsOutToSource`. Monitor for `ActiveConnectionCount` and `ErrorPortAllocation`.

Recommended alarm thresholds:
- `ActiveConnectionCount` > 90% of capacity
- `ErrorPortAllocation` > 0

### Backup & Recovery
NAT Gateways are highly available managed services. Configuration is defined in IaC. In case of deletion, it can be recreated by applying the IaC. Ensure associated Elastic IP is retained if necessary.

### Common Issues
### Outbound Connectivity Failure from Private Subnet (AZ-B)
- **Diagnosis**: Verify the route table for the private subnet in AZ-B points internet-bound traffic (0.0.0.0/0) to this NAT Gateway. Check CloudWatch logs for NAT Gateway metrics, especially `ErrorPortAllocation`.
- **Resolution**: Correct route table entries. Ensure the NAT Gateway has sufficient available ports. If the issue persists, consider a new NAT Gateway or an upgrade path if applicable.

## Rollback Procedure
1. Revert the IaC commit that modified the NAT Gateway configuration.
2. Apply the changes using the IaC tool (e.g., `terraform apply`).
3. Verify outbound internet connectivity from private subnets in AZ-B.
