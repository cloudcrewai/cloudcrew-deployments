# Runbook: Private App Subnet AZ-B

## Overview
The private application subnet in Availability Zone B hosts the application's compute resources, such as ECS tasks. These resources are not directly accessible from the internet and rely on NAT Gateways for outbound communication.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Network administrative access

## Architecture
Located within the App VPC in Availability Zone B, using CIDR block 10.0.12.0/24. Associated with a route table that directs internet-bound traffic through the NAT Gateway AZ-B. Typically hosts application servers and services.

## Operations

### Scaling
1. To increase the IP address capacity, a new subnet can be created within the VPC CIDR range in AZ-B, or the existing subnet's CIDR can be expanded if managed appropriately.
2. For enhanced availability, deploy application resources across private subnets in multiple Availability Zones.

### Monitoring
Key metrics: VPC Flow Logs for traffic analysis within the subnet and to/from the NAT Gateway. Monitor resource-specific metrics (e.g., ECS task CPU/Memory) for performance.

### Backup & Recovery
Subnets are logical constructs. Recovery involves recreating the subnet definition in IaC. The resources within this subnet (e.g., ECS tasks) have their own deployment and recovery mechanisms.

### Common Issues
### Outbound Connectivity Failures
- **Diagnosis**: Incorrect route table configuration, Security Group rules blocking outbound traffic, NAT Gateway issues.
- **Resolution**: Ensure route tables direct 0.0.0.0/0 traffic to the NAT Gateway. Verify Security Group rules permit outbound traffic. Troubleshoot the NAT Gateway.

## Rollback Procedure
1. Revert the Infrastructure as Code changes related to the private app subnet.
2. Apply the reverted configuration using Terraform.
3. Verify connectivity from resources within the subnet.
