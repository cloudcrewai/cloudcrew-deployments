# Runbook: API Gateway HTTP API

## Overview
This HTTP API acts as the entry point for all incoming requests to the serverless API. It routes requests to the appropriate Lambda functions for processing and returns the responses.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM permissions to access API Gateway

## Architecture
API Gateway is deployed in front of the Lambda API Handler, exposed via a custom domain name managed by Route53 and secured with an ACM certificate.

## Operations

### Scaling
API Gateway is a managed service and automatically scales to handle request volume. No manual scaling configuration is required.

### Monitoring
Key metrics:
- `Count`: Number of API requests received. Alarm if significantly deviates from expected baseline.
- `Latency`: API request processing time. Alarm if consistently high.
- `4XXError`: Client-side errors. Alarm if high to identify potential client issues.
- `5XXError`: Server-side errors. Alarm immediately to identify backend issues.

### Backup & Recovery
API Gateway configurations are managed via Infrastructure as Code. Recovery involves re-deploying the configuration using Terraform.

### Common Issues
### API returns 5xx errors
- **Diagnosis**: Check CloudWatch logs for the associated Lambda function for runtime errors or timeouts. Verify API Gateway integration configuration.
- **Resolution**: Address errors in the Lambda function code or adjust Lambda memory/timeout settings. Ensure correct integration targets.

## Rollback Procedure
1. Revert the relevant Infrastructure as Code (Terraform) changes for the API Gateway configuration.
2. Apply the reverted configuration using `terraform apply`.
3. Verify API functionality and monitor for errors.
