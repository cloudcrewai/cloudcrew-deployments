# Runbook: API Gateway HTTP API

## Overview
API Gateway provides the front door for the serverless API, routing incoming HTTP requests to the appropriate backend services, in this case, Lambda functions. It handles request/response transformations, authentication, and authorization.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM permissions to manage API Gateway resources
- Access to the AWS console

## Architecture
The HTTP API is deployed in a single Availability Zone and is configured with a custom domain name ('api.yourdomain.com') using an ACM certificate. It is associated with the Lambda API Handler for processing requests.

## Operations

### Scaling
1. Navigate to the API Gateway console.
2. Select 'HTTP APIs' and choose the 'Production Serverless API' custom domain.
3. Select the specific API.
4. To adjust throttling limits (if applicable and configurable via stage settings), navigate to the 'Stages' tab, select the stage, and configure 'Throttling'.

### Monitoring
Key metrics to monitor in CloudWatch for API Gateway:
- `Count` (Number of requests)
- `Latency` (End-to-end request latency)
- `4XXError` (Client-side errors)
- `5XXError` (Server-side errors)

Recommended alarm thresholds:
- `5XXError` > 0 for 5 minutes (indicating backend failures)
- `Latency` > 2000ms for 5 minutes (indicating performance degradation)

### Backup & Recovery
API Gateway configurations are managed via Infrastructure as Code (IaC). Recovery involves redeploying the configuration using the IaC pipeline.

### Common Issues
### API returns 500 Internal Server Error
**Diagnosis**: The Lambda function connected to the API Gateway is encountering an error. Check CloudWatch logs for the Lambda function associated with this API.
**Resolution**: Examine the Lambda function's logs for specific error messages and stack traces. Address the underlying code issue and redeploy the Lambda function.

## Rollback Procedure
1. Revert the IaC changes related to the API Gateway configuration.
2. Apply the reverted IaC (e.g., `terraform apply`).
3. Verify that the previous API configuration is active and functional.
