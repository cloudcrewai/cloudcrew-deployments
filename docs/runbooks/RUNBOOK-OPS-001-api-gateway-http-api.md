# Runbook: API Gateway HTTP API

## Overview
The API Gateway HTTP API acts as the front door for the serverless application, routing incoming HTTP requests to the appropriate backend Lambda functions. It provides features such as custom domain names, authentication, and request/response transformations.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM permissions to manage API Gateway resources
- Access to the custom domain's DNS records for verification.

## Architecture
Deployed as an HTTP API, integrated with AWS Lambda for backend logic. Configured with a custom domain name pointing to `api.yourdomain.com` via Route53 and an ACM certificate.

## Operations

### Scaling
API Gateway HTTP APIs scale automatically based on request volume. No manual scaling configuration is required for the API Gateway itself.

### Monitoring
Key CloudWatch metrics to monitor include:
- `Count`: Number of requests received by the API.
- `4XXError`: Number of client-side errors.
- `5XXError`: Number of server-side errors.
- `Latency`: The time taken for the API Gateway to respond to requests.

Recommended alarm thresholds:
- `5XXError` > 0 for 5 minutes (indicates backend issues).
- `Latency` > 1000ms for 5 minutes (indicates performance degradation).

### Backup & Recovery
API Gateway configurations are managed via Infrastructure as Code. In case of accidental deletion, the API Gateway can be recreated by applying the IaC. No data is stored within API Gateway itself.

### Common Issues
### 1. `403 Forbidden` errors:
- **Diagnosis**: Ensure that authentication and authorization mechanisms (e.g., Cognito) are correctly configured and that client requests include valid credentials.
- **Resolution**: Verify Cognito authorizer configuration in API Gateway and check client-side token generation and inclusion.

### 2. `502 Bad Gateway` errors:
- **Diagnosis**: Indicates a problem with the backend integration, typically the Lambda function. This could be due to Lambda timeouts, errors, or incorrect integration configuration.
- **Resolution**: Check CloudWatch logs for the associated Lambda function (`Lambda API Handler`) for specific error messages. Verify the Lambda integration settings in API Gateway.

## Rollback Procedure
1. Revert the Infrastructure as Code commit that modified the API Gateway configuration.
2. Apply the changes using the IaC tool (e.g., `terraform apply`).
3. Verify that the API Gateway is functioning as expected and that requests are routed correctly.
