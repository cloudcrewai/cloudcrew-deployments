# Runbook: Private Subnet AZ-B

## Overview
Private Subnet AZ-B resides in Availability Zone 'b' and is designed to host backend resources that should not be directly accessible from the internet. Outbound internet access is provided via the NAT Gateway AZ-B.

## Prerequisites
- AWS CLI configured with appropriate credentials.
- IAM permissions to describe VPC, Subnets, and Route Tables.

## Architecture
Part of the 'App VPC' with CIDR block 10.0.12.0/24 in Availability Zone 'b'. Its route table directs internet-bound traffic to NAT Gateway AZ-B.

## Operations

### Scaling
Subnet scaling involves expanding the CIDR block if it becomes exhausted or adding new subnets. This is managed via Infrastructure as Code changes to `var.private_subnet_cidrs`.

### Monitoring
Monitor the IP address utilization within the subnet. Track traffic flow through associated route tables and security groups. Monitor resources deployed within this subnet.

### Backup & Recovery
Subnet configurations are managed by Infrastructure as Code. If a subnet is accidentally deleted, re-running the IaC apply will recreate it.

### Common Issues
### Resources in Private Subnet AZ-B cannot reach the internet
1. Verify the route table associated with this subnet has a default route (0.0.0.0/0) pointing to NAT Gateway AZ-B.
2. Ensure NAT Gateway AZ-B is healthy and functional.
3. Check security groups and Network ACLs for both the instances and the subnet's route table.

## Rollback Procedure
1. Revert the Infrastructure as Code commit that modified or deleted the Private Subnet AZ-B.
2. Execute the IaC apply command.
3. Verify network connectivity for resources within the subnet.
