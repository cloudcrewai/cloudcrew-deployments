# Runbook: Public Subnet AZ-B

## Overview
This is a public subnet within Availability Zone B of the 'App VPC'. It is configured to allow internet access via an Internet Gateway and hosts resources that require direct or indirect internet connectivity, such as NAT Gateways.

## Prerequisites
- AWS CLI configured with appropriate permissions to manage VPC resources.
- Understanding of subnet CIDR ranges and routing.

## Architecture
Part of the 'App VPC' (10.0.0.0/16). Uses CIDR block 10.0.2.0/24. Associated with Route Table that directs internet-bound traffic (0.0.0.0/0) to the Internet Gateway. Hosts the NAT Gateway for AZ-B.

## Operations

### Scaling
Subnet scaling is not a direct concept. To accommodate more resources, consider:
1. Extending the CIDR range if the VPC has available space.
2. Creating additional subnets in the same AZ or different AZs.

### Monitoring
While subnets themselves don't have direct CloudWatch metrics, monitor resources within the subnet, such as:
- NAT Gateway metrics (if applicable)
- Elastic IP utilization
- Network ACL logs for traffic patterns and potential denies.
Recommended Alarm Thresholds: Monitor for any denied traffic in Network ACLs associated with this subnet.

### Backup & Recovery
Subnets are configuration elements of a VPC. Backups are not applicable. In case of deletion, a new subnet would need to be recreated with the same CIDR and associated route tables.

### Common Issues
### IP Address Exhaustion
*   **Diagnosis**: New resources cannot be launched within the subnet due to lack of available IP addresses.
*   **Resolution**: Review current IP usage within the subnet's CIDR. If necessary, expand the subnet's CIDR range (if VPC has capacity) or create a new subnet. 

### Routing Issues
*   **Diagnosis**: Resources in the subnet cannot reach the internet or other intended destinations.
*   **Resolution**: Verify the Route Table associated with this subnet. Ensure `0.0.0.0/0` traffic is routed to the Internet Gateway if it's intended to be a public subnet, and that specific routes for internal VPC communication are present.

## Rollback Procedure
1. Revert any IaC changes related to the subnet's CIDR or Route Table associations.
2. Apply the reverted IaC.
3. Verify connectivity and resource status.
