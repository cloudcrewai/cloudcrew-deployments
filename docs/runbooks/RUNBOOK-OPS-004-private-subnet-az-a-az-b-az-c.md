# Runbook: Private Subnet AZ-A, AZ-B, AZ-C

## Overview
These private subnets are network segments within the VPC that do not have a direct route to the Internet Gateway. Resources placed here, such as application servers or databases, are shielded from direct internet access.

## Prerequisites
- AWS CLI configured with appropriate permissions
- VPC with NAT Gateways or VPC Endpoints for outbound access
- Route tables associated with these subnets

## Architecture
These subnets (10.0.11.0/24, 10.0.12.0/24, 10.0.13.0/24) reside in separate Availability Zones (a, b, c respectively) within the 'App VPC'. They are configured with route tables that direct internet-bound traffic through a NAT Gateway (located in a public subnet) or via VPC Endpoints.

## Operations

### Scaling
Similar to public subnets, the IP address range is fixed. To scale capacity, create new subnets with additional CIDR blocks. Resource scaling within these subnets is managed by their respective services (e.g., ECS Auto Scaling).

### Monitoring
Monitor CloudWatch metrics for Network ACLs associated with these subnets for DENY activity. Analyze VPC Flow Logs for traffic patterns. Monitor resource utilization (e.g., IP address exhaustion).

### Backup & Recovery
Subnet configurations are part of the overall VPC definition and are managed via Infrastructure as Code. Recovery involves reapplying the IaC configurations.

### Common Issues
### Resources in private subnets cannot reach the internet or external services
- **Diagnosis**: Verify the subnet's route table has a default route (0.0.0.0/0) pointing to a NAT Gateway or VPC Endpoint. Ensure Security Groups and Network ACLs associated with the resources allow outbound traffic to the required destinations. Check NAT Gateway status and its public subnet's route table.
- **Resolution**: Correct the route table configuration. Adjust Security Groups and Network ACLs. Verify NAT Gateway health and its associated routes.

## Rollback Procedure
1. Revert the Infrastructure as Code (IaC) changes related to the private subnets.
2. Apply the reverted IaC using the deployment tool (e.g., `terraform apply`).
3. Verify resources within the private subnets have the expected network connectivity.
