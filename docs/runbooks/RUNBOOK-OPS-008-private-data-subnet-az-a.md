# Runbook: Private Data Subnet AZ-A

## Overview
The private data subnet in Availability Zone A is designated for sensitive data services, such as RDS databases. It resides within the VPC but is not directly reachable from the internet, enhancing security.

## Prerequisites
- AWS CLI configured with appropriate permissions
- Network administrative access

## Architecture
Located within the App VPC in Availability Zone A, using CIDR block 10.0.21.0/24. Associated with a route table that may only allow traffic from specific security groups (e.g., application subnets) or has no internet-bound route.

## Operations

### Scaling
1. To increase IP address capacity, a new subnet can be created within the VPC CIDR range in AZ-A or the existing subnet's CIDR can be expanded.
2. For high availability of data services, these subnets are typically part of a multi-AZ deployment strategy.

### Monitoring
Key metrics: VPC Flow Logs for traffic analysis within the subnet and to/from authorized subnets. Monitor database-specific metrics for performance and availability.

### Backup & Recovery
Subnets are logical constructs. Recovery involves recreating the subnet definition in IaC. Data services within this subnet (e.g., RDS) have their own dedicated backup and recovery procedures.

### Common Issues
### Database Unavailability
- **Diagnosis**: Security Group rules blocking traffic from application subnets, incorrect routing to the database endpoint, or issues with the database service itself.
- **Resolution**: Ensure Security Group rules allow inbound traffic from application Security Groups on the database port. Verify network routing. Check the status of the database service.

## Rollback Procedure
1. Revert the Infrastructure as Code changes related to the private data subnet.
2. Apply the reverted configuration using Terraform.
3. Verify connectivity from authorized application resources to the data services.
