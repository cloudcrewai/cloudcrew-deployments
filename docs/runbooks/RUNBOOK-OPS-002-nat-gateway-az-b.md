# Runbook: NAT Gateway AZ-B

## Overview
The NAT Gateway in Availability Zone B provides outbound internet access for resources in private subnets within that AZ. This ensures that instances in private subnets can reach external services securely without being directly exposed to the internet.

## Prerequisites
- AWS CLI configured with necessary IAM permissions for EC2 and VPC operations.
- Access to the AWS Management Console.

## Architecture
Deployed within the public subnet of Availability Zone B, NAT Gateway AZ-B utilizes a dedicated Elastic IP address. The route tables associated with private subnets in Availability Zone B are configured to direct internet-bound traffic through this NAT Gateway.

## Operations

### Scaling
1. NAT Gateways are designed for high availability across Availability Zones. The presence of NAT Gateway AZ-A ensures redundancy.
2. AWS automatically scales the throughput capacity of NAT Gateways to meet demand.

### Monitoring
Key CloudWatch metrics for NAT Gateway AZ-B:
- `BytesInFromSource`: Traffic originating from private subnets in AZ-B.
- `BytesOutToDestination`: Traffic destined for the internet from AZ-B.
- `ActiveConnectionCount`: Current number of active connections.
- `ErrorPortAllocation`: Potential indication of resource exhaustion.

Recommended alarm thresholds:
- `ActiveConnectionCount` approaching its limit.
- `ErrorPortAllocation` exceeding 0.

### Backup & Recovery
NAT Gateways are a fully managed AWS service; therefore, backups are not applicable. Failover to another AZ's NAT Gateway is automatic in case of an AZ-specific outage.

### Common Issues
### NAT Gateway Failures
**Diagnosis**: Verify the NAT Gateway's operational status in the AWS console. Check associated route tables to confirm they direct traffic to the correct NAT Gateway ID and that the gateway resides in a public subnet with internet connectivity.
**Resolution**: Ensure the NAT Gateway is healthy, its Elastic IP is correctly assigned, and route table configurations are accurate. Address any connectivity issues with the public subnet or Internet Gateway.

### Performance Degradation
**Diagnosis**: Monitor `BytesInFromSource` and `BytesOutToDestination` metrics for sustained high utilization. Examine the `ActiveConnectionCount` to see if it's nearing the NAT Gateway's capacity limit.
**Resolution**: If consistent high utilization is observed, consider if the workload requires a higher capacity NAT Gateway or if traffic can be optimized. Ensure other network components are not bottlenecks.

3. Confirm the NAT Gateway is removed or in the expected state post-rollback.
