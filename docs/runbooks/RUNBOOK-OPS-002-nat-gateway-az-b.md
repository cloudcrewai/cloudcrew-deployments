# Runbook: NAT Gateway AZ-B

## Overview
The NAT Gateway in Availability Zone B enables instances in private subnets to connect to the internet or other AWS services, but prevents the internet from initiating connections with those instances.

## Prerequisites
- AWS CLI configured with appropriate permissions
- IAM permissions to manage VPC resources
- Access to CloudWatch logs for monitoring.

## Architecture
The NAT Gateway is deployed in the public subnet of Availability Zone B. It is associated with an Elastic IP address and is configured with a route in the private subnet's route table to direct outbound internet traffic through it.

## Operations

### Scaling
1. **Manual Scaling**: NAT Gateways are managed services and do not require manual scaling. AWS handles availability and capacity.
2. **Auto-Scaling**: Auto-scaling for NAT Gateways is not applicable as it's a managed service. High availability is achieved through multiple NAT Gateways across different Availability Zones.

### Monitoring
Key CloudWatch metrics to monitor:
- `BytesInFromSource` and `BytesOutToSource`: To track data transfer volume.
- `ActiveConnectionCount`: To monitor the number of active connections.
- `ErrorPortAllocation`: To detect issues with port allocation.
- **Recommended Alarm Thresholds**: High `ErrorPortAllocation` should trigger an alarm. Sustained high `ActiveConnectionCount` could indicate a need for further investigation into application traffic patterns.

### Backup & Recovery
NAT Gateways are a highly available AWS managed service. There is no direct backup or restore procedure for a NAT Gateway itself. If a NAT Gateway becomes unavailable, traffic is automatically routed to other NAT Gateways in different Availability Zones if configured.

### Common Issues
### NAT Gateway Unreachable
**Diagnosis**: Check CloudWatch metrics for `BytesInFromSource` and `BytesOutToSource`. Ensure the route table for the private subnet correctly points default outbound traffic to this NAT Gateway. Verify the NAT Gateway has an Elastic IP associated and is in a public subnet.
**Resolution**: Recreate the NAT Gateway if it's found to be unhealthy. Ensure the associated Elastic IP is re-associated if necessary. Correct routing configurations in the private subnet's route table.

## Rollback Procedure
1. **Revert IaC**: If the NAT Gateway was provisioned via Infrastructure as Code, revert the relevant changes and re-apply.
2. **Replace NAT Gateway**: If the current NAT Gateway needs replacement, create a new one and update the route tables of private subnets to point to the new NAT Gateway.
3. **Associate Elastic IP**: Ensure the Elastic IP address is associated with the new NAT Gateway.
4. **Verify Connectivity**: Test outbound internet connectivity from instances in private subnets.
