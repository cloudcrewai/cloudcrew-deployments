# Runbook: NAT Gateway AZ-B

## Overview
The NAT Gateway in Availability Zone B enables instances in private subnets to connect to the internet or other AWS services, but prevents the internet from initiating a connection with those instances. It is crucial for outbound traffic from private subnets.

## Prerequisites
- AWS CLI configured with appropriate permissions for NAT Gateway management.
- IAM permissions to describe VPC, Subnets, and Elastic IPs.

## Architecture
Resides in the public subnet AZ-B. Associated with an Elastic IP address. Routes traffic from private subnets in AZ-B to the internet via the Internet Gateway.

## Operations

### Scaling
1. NAT Gateways are managed services and automatically scale.
2. To increase throughput, consider deploying additional NAT Gateways in different Availability Zones and updating route tables for private subnets to utilize them.

### Monitoring
Key metrics to monitor in CloudWatch:
- `BytesInFromSource` (high values indicate heavy inbound traffic to the NAT Gateway)
- `BytesOutToSource` (high values indicate heavy outbound traffic from the NAT Gateway)
- `ActiveConnectionCount` (high values may indicate potential bottlenecks)
- `ErrorPortAllocation` (should remain at 0)
Recommended Alarm Thresholds:
- `ActiveConnectionCount` > 50000 for 5 minutes
- `ErrorPortAllocation` > 0 for 1 minute

### Backup & Recovery
NAT Gateways are AWS managed resources. Backups are not applicable. In case of failure, a replacement NAT Gateway will be automatically provisioned. Failover to NAT Gateway AZ-A can be achieved by updating route tables.

### Common Issues
### High Connection Count
*   **Diagnosis**: `ActiveConnectionCount` is consistently high, approaching limits.
*   **Resolution**: Ensure proper connection closing by applications. Consider distributing traffic across multiple NAT Gateways if feasible, by updating route tables. 

### Intermittent Connectivity Issues
*   **Diagnosis**: Applications in private subnets experience intermittent outbound connectivity failures.
*   **Resolution**: Check CloudWatch metrics for NAT Gateway. Verify Elastic IP association and subnet routing. Ensure sufficient available IP addresses in the CIDR range of the associated public subnet.

## Rollback Procedure
Rollback is not applicable for NAT Gateway failures as it's a managed service. Failover to an alternate NAT Gateway is the primary recovery mechanism.
