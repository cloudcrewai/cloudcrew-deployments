# Runbook: ElastiCache Redis Cluster

## Overview
The ElastiCache Redis cluster provides a high-performance, in-memory data store used for caching frequently accessed data, reducing database load and improving application response times.

## Prerequisites
- AWS CLI configured with appropriate permissions
- ElastiCache cluster creation permissions
- VPC with appropriate subnets and security groups configured
- Parameter group configured

## Architecture
The ElastiCache Redis cluster is deployed across multiple Availability Zones within private subnets. It is configured with a security group that allows inbound connections from the ECS service's security group on the Redis port (6379).

## Operations

### Scaling
1. Navigate to the ElastiCache console.
2. Select the Redis cluster.
3. Click 'Modify'.
4. To scale compute, adjust the 'Number of replicas' or 'Shards' (for Redis Cluster mode enabled). For instance type scaling, choose a new node type. Note: Scaling compute or changing node types may involve a brief interruption or require careful planning for high availability.
5. To scale data capacity, increase the number of shards or replicas.

### Monitoring
Key CloudWatch metrics: EngineCPUUtilization, CacheHits, CacheMisses, NetworkBytesIn, NetworkBytesOut, CurrConnections, ReplicationLag (if applicable). Recommended alarm thresholds: EngineCPUUtilization > 85%, CacheMisses significantly increasing relative to CacheHits, CurrConnections high.

### Backup & Recovery
Redis backup is configured with a retention period of X days (default 7, configurable). Backups are initiated automatically. To restore: 1. Navigate to the ElastiCache console. 2. Select the cluster. 3. Click 'Actions' -> 'Restore from backup'. 4. Choose the desired backup and provide a new cluster ID. RTO depends on the dataset size but is typically within minutes for smaller datasets.

### Common Issues
Consult CloudWatch logs for errors.

## Rollback Procedure
1. Revert the IaC commit that modified the ElastiCache cluster configuration.
2. Apply the reverted IaC using `terraform apply`.
3. If a restore was performed, ensure the application is pointing to the correct Redis endpoint.
4. Verify ElastiCache connectivity and performance.
